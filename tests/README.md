# tests/ — тесты репозитория

Проверки структуры и наполнения. Живут в репозитории, а не во временном
каталоге: тест, который не переживает пересоздание рабочей среды, не защищает
ничего.

> **База пути.** Непомеченные пути в этом документе считаются от корня
> репозитория. Префиксы `CONVENTIONS.md` §10.1 применяются там, где путь
> указывает на раздел флешки.

## Запуск

```bash
python3 tests/run-all.py            # все проверки
python3 tests/test_repo.py          # каркас и инварианты всего репозитория
python3 tests/test_stage42.py       # наполнение tools/rescue/
```

Каждый файл завершается кодом `0` при успехе и `1` при любой ошибке.

## Что проверяется

| Файл | Область |
|------|---------|
| `test_repo.py` (159 проверок) | Каркас: обязательные файлы, шаблоны, заглушки с README рядом, `manifest.csv` (поля, LF, дубли, SELF-HASH), `ventoy.json`, `algorithm.md` для каждой станции, CJK-вкрапления, битые относительные ссылки |
| `test_stage42.py` (89 проверок) | Группа `tools/rescue/`: структура, индексы на каждом уровне, заполненность README по шаблону, матрица решений, зафиксированные ограничения (EFS, DPAPI, BitLocker, TRIM, `reg unload`), отсутствие дублей утилит из Strelec, регрессия предыдущих этапов |
| `test_ps1_lint.py` (273 проверки) | Статический разбор всех 14 `.ps1` без PowerShell (задача A2): UTF-8 без BOM, LF без CRLF, отсутствие табов и висячих пробелов, парность `{}`/`()`/`[]` **после** вырезания строк и комментариев, `#Requires -Version 5.1` до первого исполняемого кода, `Set-StrictMode` и `$ErrorActionPreference` по одному разу, позиции маркеров here-string, наличие пары `.sh`. Не утверждает, что скрипты работают, — утверждает, что они разберутся |

Таблица неполная: перечислены только тесты с самостоятельной областью. Полный
список — в `TESTS` внутри `run-all.py`.

## Правила теста

- Тест обязан **падать** на нарушении. Проверка, которая проходит и на
  сломанном состоянии, ничего не проверяет.
- Отрицательные сценарии прогоняются вручную при изменении правила: удалить
  файл, сбить поле в `manifest.csv`, убрать обязательный раздел README,
  перевести `manifest.csv` в CRLF.
- Там, где тест содержит собственный разборщик, отрицательные сценарии
  встроены в сам тест, а не прогоняются вручную: блок `[9]` в
  `test_ps1_lint.py` подаёт на вход заведомо сломанные фрагменты PowerShell и
  требует, чтобы разборчик их поймал, плюс корректные фрагменты, на которых
  ложное срабатывание недопустимо. Без этого тест доказывал бы только то, что
  файлы прошли, но не то, что он вообще способен что-то поймать.
- Тест не должен дублировать `scripts/repo-validate.sh`. Валидатор проверяет
  соответствие `CONVENTIONS.md`; тесты проверяют наполнение и содержательные
  требования, которые в соглашения не уложить.

## История

До Этапа 4.2 тесты этапов 2, 3, 3c, 3d и 4.1 хранились в `/tmp` и были
утеряны при пересоздании рабочей среды — 183 проверки. Восстановлены в виде
`test_repo.py` (каркасные инварианты) и `test_stage42.py`. Проверки,
специфичные для утраченных этапов, перенесены в `test_repo.py` частично;
полное их восстановление — отдельная задача.
