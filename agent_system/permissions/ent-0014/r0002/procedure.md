# Локальный порядок оценки разрешения r0002

1. Установить exact protected ENT14r2/dependencies/interpreter. Проверить внешний
   источник owner decision и цель/предмет/пределы, не трактовать implementation
   delegation как grant. Для private основания сохранить источник/полный текст/
   форму quote либо summary. Код не аутентифицирует owner identity/сообщение.
2. Составить immutable subject с exact candidate/registry/entity known set/payload/
   coverage-description/procedure/prompt refs. Не считать descriptor готовым только
   из-за слова ready. Для текущего ENT13r1 готовность заведомо incomplete12/34.
3. Отдельные permission events получают UUID и exact subject. Release ≠ export;
   export содержит exact release parent/allowlist/destination/procedure/prompt/
   export_id. Не добавлять их в старый catalog/approvals. Сохранять известные
   deny/revoke, не выбирать удобную дату. Runtime source/records local вне Git.
4. Owner-controlled authority context должен устанавливаться независимо от source,
   после относящегося реального согласия на **эти** decisions. Зафиксировать
   known/approved refs и generation. Не создавать approved set автоматически из
   всех найденных events. establish_local_authority с explicit True/external pin —
   acknowledgment этой предпосылки, не механизм её доказательства.
5. В одном module instance получить authority, затем closed request/pins и вызвать
   evaluate_permission. Проверить status/exact report pins/known blocks. Для
   действующего candidate вызывать check_current_candidate с теми же pinned bytes
   и actual native inputs: recognition без native checks не proof composition.
6. Интерпретация: recognized intent и authority_valid не равны release_allowed.
   В r2 все transition/action/activation flags false, performed=false. Incomplete
   guard/known block/failure/unsupported останавливает затронутый переход.
7. При old-view/generation неопределённости остановить action; не придумывать
   свежесть/rollback protection. Future R5 actuator обязан получить current head,
   exclusive claim и safe destination, R6 — readiness. Эти механизмы в r2 отсутствуют.
   Повтор request не считается доказанно одноразовым. Нельзя копировать/публиковать
   output ради проверки запрета. Partial не удалять/не откатывать автоматически.
8. Передать safe report: точные refs/status, какие semantics verified и какие
   source/owner/readiness/state/actuation условия не проверены. Не публиковать
   raw private context/источник согласия/пути среды. Исторические grants не
   activate в новой среде. Новое решение/контекст — новые pinned bytes/оценка.

Для проверки установленной семантики вызвать verify.py approved isolated Python.
Он создаёт **synthetic** owner contexts только в памяти и вызывает native incomplete
checker, не создаёт настоящие owner decisions и не выполняет переход. Этот test
entry не bootstrap authority для реального выпуска. Нет обязательного /tmp recipe,
нового signer/ключей/стороннего evaluator. Настоящий local importer/store/current
head workflow предстоит отдельно; не заявлять его сделанным из этих API.
