# ENT12r2 — inactive preparation procedure

Полный local preparation profile, применяет точный ENT12r1 governance G00–G09,
ENT11r2 methodology и ENT1r1 core без копии/ослабления. Для **этого** явно
выбранного r2 entry — prompt.md r2; старый G04/r1 entry/consumers не переключены.
Sources: owner B/P1ред2, conditional implementation delegation и согласованное
продолжение R5. Version/status/bytes/depends_on — единственный registry.

1. Выбрать exact roots/context=export/agent_system.transfer и цель подготовки.
   Это лишь scope запроса проверок, не export instruction/permission. Source root
   отдельно, не в переносимом request. Нужен protected installed interpreter/
   namespace; foreign input code никогда не исполнять.
2. До capture зафиксировать request+plan bytes/external pins, точные procedure/
   prompt/seed refs, own ENT12r2 component. Не использовать latest/даты/имена как
   доверие. Explicit inactive acknowledgment обязателен. Collector installed_packet
   допускается только по acknowledged independently protected installation:
   наблюдённые pins остаются caller_supplied_not_authenticated, не owner authority.
3. Native ENT9r2 capture получает только declared files и полный observed ledger,
   проверяет bytes/graph/approvals/known export restrictions. Unexpected negative/
   unknown/missing event не фильтровать. Private/local/project paths не разрешены
   этим профилем. Есть только bounded Linux acquisition, не universal runtime.
4. По тому же single capture собрать exact records/closure/materializable path
   allowlist. Не reread source для descriptor. Seed ENT13r1 проверить отдельно
   на его original components. Все25historical rows сохранить open без повышения
   их checks defined_only в actual выполненные tests нового composition.
5. Получить prepared_inactive metadata descriptor. Это НЕ physical portable kit,
   NOT new coverage/readiness result. Для R6 отдельно подтвердить exact subject,
   missing evidence levels и границы каждого gap. Known no-block не permission.
6. При необходимости persist_preparation пишет **только metadata** через ENT18
   private EvidenceStore. Он не копирует normative payloads в bundle/destination,
   не вызывает claim manager/permission import. Receipt/index pins хранить вне
   source/high-water policy отдельно. Verify_evidence — bytes/inventory/readback,
   не повтор acquisition/semantic replay. Private evidence остаётся вне Git.
7. Failure/unsupported/limit: stop, report code/outcome, no success descriptor.
   При write failure частичное evidence сохраняется; no automatic retry/delete/
   rollback/adopt. Новые inputs/procedure/prompt требуют нового preparation run,
   старые metadata/approvals не меняются. Нет exactly-once для preparation UUID.
8. Никаких release/export/activation действий. R4/I2b durable claims, R6 positive
   readiness, R5 actual exporter и R7/R8 environment/activation ещё не реализованы.
   History/bindings/assents/секреты/private architecture не входят автоматически.
   Не объявлять всю систему готовой по количеству артефактов или зелёным tests.
