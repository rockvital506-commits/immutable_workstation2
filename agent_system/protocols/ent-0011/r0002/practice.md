# Практическая оценка применения методологии r0002

## Назначение и границы

Операционализация W09, не второй источник W01–W09 и не automated evaluator.
Применима к существенной предметной задаче и изменению самой системы в пределах
имеющегося полномочия. Model tests/хэш/повтор recorded journal не доказывают
качество предметного решения, реальность наблюдения или соблюдение всех правил.
Для простого ответа применять соразмерность W00; дополнительные формы не цель.

## До действий

Зафиксировать task_id, цель, exact inputs/source refs и baseline (например Git
commit), критерии до действия, разрешённый diff/полномочие, required checks,
условия stop, недоступные сведения и последствия. Открытые учебные данные явно
пометить как учебные; visibility expected checks указать, не обещать blind test.
Если входы/критерии меняются существенно, сохранить исходный baseline и новое
основание до продолжения, не улучшать оценку задним числом.

## Наблюдение и проверка

Для относящегося W вести короткую цепочку: вход/наблюдение → решение и основание
полномочия → действие → результат → способ проверки и ограничение вывода.
Проверить предметный результат: например арифметику/выполнимость/смысл изменения,
не только JSON/hash/число tests. Не создавать новый framework, если применимы
имеющиеся безопасные средства. Не собирать секреты для журнала.

Контролируемый defect допустим только в безопасном учебном входе, с заранее
указанным affected stop/правом коррекции. Не намеренно выполнять опасное/неверное
действие агента ради FAIL. Сохранить первоначальный отказ, диагностическое
основание и коррекцию; повторить affected checks/regressions. Если отказа не
наблюдалось, не заявлять его проверенным. Отложенное сохранять с условием возврата,
не активировать его автоматически. Независимые безопасные части могут продолжаться.

## Карта результата

Для каждого применимого W указать источник, ссылку на наблюдение/артефакт,
предметный check, результат и ограничение. Допустимые локальные labels:
observed_supported, observed_failed, not_observed, not_applicable (с причиной).
Частично подтверждённое не повышать до полного observed_supported: указывать,
какой именно фрагмент наблюдался. Эти labels не catalog status/permission.
Отдельно указать evidence_level: model_review, local_execution, operator_observation
или real_environment в фактически выполненной области. reviewer_level обозначать
как self_review, owner_review либо independent_review только по факту такого review;
не назначать отсутствующего независимого reviewer и не придумывать его результат.
review_pending сохраняется явно. Операторские statements не execution authentication.

## Итог и продолжение

Сопоставить с baseline: что выполнено, чем проверено, где failure/unknown,
что осталось/когда вернуться. Не объявлять общую гарантию поведения или compatible
release из двух случаев. Model tests остаются model_review, даже если рядом
есть local practice. Правила/формат журнала не подтверждают истинность его claims.
Согласие на задачу не review результата. При изменении системы отдельно проверить
immutable refs, входящие зависимости/candidates/bindings и нужные regressions;
новую revision не включать автоматически в old payload/активную связку.
No release/export/activation permission из этой оценки. Условное implementation
делегирование используется только после подтверждения относящихся условий.
