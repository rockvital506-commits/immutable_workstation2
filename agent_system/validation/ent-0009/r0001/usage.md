# Исполнитель одного закреплённого плана — локальная композиция слоёв

## Статус и точные зависимости
ENT-0009 r0001 — check: execute.py, verify.py, usage.md. Точная depends_on:
ENT-0008 r0001; транзитивный профиль — ENT-0005 r0003/ENT-0006 r0003 и их
immutable зависимости. Новых библиотек нет: разрешённая isolated среда
jsonschema 4.26.0 и прежний hash-lock. Source acquisition только Linux x86-64
с openat2/proc и прежними ограничениями. Исторические версии не меняются.

Это исполнитель объявленного плана, НЕ отдельный offline verifier произвольного
чужого bundle, НЕ аутентификация плана и НЕ полный валидатор/выпуск/активация.
Он создаёт результаты собственных вызовов доверенных установленных инструментов,
не принимает готовые child reports/callbacks/профили из входного дерева.

## API и доверенная установка
execute_plan(root, plan_bytes, expected_plan) возвращает report_bytes и documents
(dict SHA-256 -> точные bytes плана/полученных дочерних документов).
expected_plan — ОБЯЗАТЕЛЬНЫЙ заранее закреплённый {sha256,size_bytes} исходного
плана из отдельного доверенного основания caller. Изменение context/selection
с тем же expected_plan блокируется; автоматического обновления ожидания нет.
Это проверка совпадения, не подтверждение происхождения expected_plan.
Root — локальный pathname/native Path вне плана, без пользовательских callbacks.

Сам execute.py должен быть доверенно установлен caller как часть точного
согласованного состава; самоодобрения через непроверенный source registry нет.
21 полный artifact tuple installed dependency closure зафиксирован в коде;
перед загрузкой сверяются SHA/size, чтение bounded ожидаемым размером+1.
Ресурсы/модули загружаются ТОЛЬКО из фиксированного установленного дерева,
не из root/входного registry. Неизвестный профиль плана отвергается Schema;
недоступная/изменённая установка даёт unsupported preflight, без latest/fallback.

Доверенная установка, kernel/mount/proc и интерпретатор не должны изменяться
противником в процессе выполнения. Проверка хэша перед runpy не является
атомарной загрузкой при атакующем, пишущем в установленное дерево. Source не
должен иметь возможности менять эту установку. Совпадение root с installed
checkout допустимо только для доверенной интеграционной фикстуры, не как защита
от чужого writable source. При необходимости другой модели потребуется новая
проверенная реализация, а не расширение этого обещания.

## Preflight без чтения source
Исходные bytes плана не более 16 MiB, exact hash/size, UTF-8 strict JSON,
LF и один финальный LF; Schema ENT-0008 r0001. Затем проверяются уникальность
paths между всеми группами (включая registry), native integer sizes,
совпадение catalog_id у selection, максимум 10000 файлов/64 MiB суммарно.
Schema ограничивает каждый файл 16 MiB и не допускает role/команды/absolute
root/activation. Ожидания не формируются из обнаруженного source.

До валидного плана/профиля ошибка — PlanBlocked(code, unsupported=False|True),
без частного пути/содержимого. Не выдумывается plan_id/run report, когда план
не удалось подтвердить. Чтение installed tools не является чтением source.
Preflight не создаёт разрешение и не изменяет ожидания владельца.

## Исполнение и границы композиции
1. read_set получает registry в обычной группе, artifacts и decisions под
   одним закреплённым корнем, с exact inventory до/после.
2. Проверяются полнота byte maps, их SHA/size, полные metadata inputs evidence,
   признак одного корня, совпадение инвентарей/ожидаемых имён и отсутствие допуска.
3. Child evidence сериализуется один раз в UTF-8/LF, ссылка вычисляется по
   полученным bytes. Затем registry извлекается из этой же byte map, catalog_id
   сопоставляется с планом. Нет повторного чтения source между слоями.
4. В check_catalog передаются эти bytes, копия selection и точный context.
   Для успешного/blocked child сверяются все input hashes, выбранные roots в
   closure, subjects/context/events inputs/status/blocks и запрет admission.
   Семантику closure вычисляет только установленный ENT-0006: второго алгоритма
   графа здесь нет. Отдельный verifier произвольного чужого closure не заявлен.
5. Полный child report сохраняется без правки его not_checked/diagnostics.
   Envelope получает KNOWN_SCOPE_BLOCK summary при известном запрете. Схема
   оболочки проверяется перед возвратом. Везде overall_admission=not_evaluated,
   transition_allowed=false и полный фиксированный not_checked ENT-0008.

Отказ acquisition оставляет binding=not_run, без повторного использования
старого результата. Отказ binding сохраняет ссылку успешного acquisition.
Ожидаемые ReadBlocked/PlanBlocked и известные ошибки слоя нормализуются в коды;
без дочернего результата evidence отсутствует. Неизвестная авария/KeyboardInterrupt
не перехватываются как успех: финальный run report отсутствует. Ошибка финальной
сериализации/Schema также может дать PlanBlocked без финального report; caller
должен считать run незавершённым, не извлекать PASS из частичных данных.

Документы ограничены 16 MiB, превышение не обрезается. JSON сериализация in-memory,
не потоковая; память и повторное хэширование — осознанные издержки. Source
byte maps не возвращаются/не архивируются автоматически: documents достаточно
для фиксации claims/ссылок, но НЕ для независимого повторного доказательства
всех исходных байтов или наблюдений источника. Потребность в таком архиве и
проверяющем bundle остаётся отдельной задачей.

## Локальное хранение и пределы
Функция не пишет файлы, не исполняет operation из плана и не экспортирует.
operation=export/activate — контекст проверки запретов, не команда действия.
Caller сохраняет report_bytes и documents вне Git/экспорта, неизменно и с
проверкой точных ссылок. Documents могут содержать private symlink targets;
не публиковать автоматически. UUID run_id новый при каждом запуске; plan bytes
не изменяются. Возврат результата не разрешает выпуск, экспорт или активацию.

Как и модель B: только переданные/полученные bytes и наблюдаемые состояния,
не атомарность, не все невидимые события, не глобальная полнота/будущие отзывы.
Plan/source authentication, ядро, совместимость среды, release и activation
по-прежнему not_checked. Чужой сфабрикованный bundle этой функцией не проверяется.

## Обоснование и проверки
Плюсы: повторно используются доказанные слои без копии ядра/графа; обязательный
внешний pin плана; ранние отказы; один источник bytes между слоями; дочерние
результаты не теряются при унификации статусов. Минусы/риски: доверенная установка,
дополнительное чтение/хэширование 21 installed artifact при каждом запуске,
in-memory byte maps и JSON, нет независимого bundle verifier/аутентификации.
Ускорение и максимальная нагрузка не обещаны, уменьшать проверки ради скорости
нельзя. Пределы и один локальный замер — не универсальный benchmark.

python agent_system/validation/ent-0009/r0001/verify.py в разрешённой isolated
среде: 30 тестов без skips/errors/failures. Синтетические фикстуры: positive,
точные ссылки, plan/context/selection/child inputs/evidence substitution,
preflight limits/duplicates/catalog/types, unknown profile/engine/pins, extra
ledger/changed bytes, scoped block, отказы/прерывание и отсутствие записи source.
