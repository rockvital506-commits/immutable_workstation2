# Структурные регрессионные испытания базовой схемы

## Назначение, область и зависимости
ENT-0004 r0002, kind check. Нормативная зависимость: ENT-0003 r0002 того же
каталога; её точные зависимости остаются транзитивными. В состав этой проверки
входят verify.py, requirements-linux-cp311.lock и настоящий usage.md.
Проверка подтверждает заданные структурные сценарии схемы и текущие образцы
registry/approve_revision, не даёт общего допуска каталога.

## Среда и воспроизводимость
Проверенная среда: Linux x86-64, CPython 3.11.2. Lock фиксирует шесть пакетов
и SHA-256 конкретных wheels, в том числе платформенный wheel rpds-py.
Другие платформы и версии Python этим lock не подтверждены. Дополнительные
format extras не устанавливаются. Подготовка окружения имеет сетевой этап;
сама проверка не загружает внешние схемы и не должна требовать сети.

Из корня репозитория, при наличии Python 3.11 и доступа к PyPI:

```text
python3 -m venv ../.venv/immutable-agent-system
../.venv/immutable-agent-system/bin/python -m pip install --index-url https://pypi.org/simple --require-hashes --only-binary=:all: -r agent_system/validation/ent-0004/r0002/requirements-linux-cp311.lock
../.venv/immutable-agent-system/bin/python -m pip check
../.venv/immutable-agent-system/bin/python agent_system/validation/ent-0004/r0002/verify.py
../.venv/immutable-agent-system/bin/python tests/run-all.py
```

В самостоятельном комплекте без тестов исходного репозитория применяется
прямой запуск verify.py; положение относительно корня agent_system сохраняется.
Команда не создаёт и не активирует локальную связку. Среда вне дерева репозитория и скачанные
wheels не входят в каталог/экспорт. Не выполнять тихую установку из проверяющего
кода: отсутствие зависимости должно завершать запуск ошибкой, не skip/PASS.
Команды создания среды предназначены для новой/выбранной изолированной среды,
не для изменения неизвестной чужой установки. Внешнее размещение среды
не загрязняет инвентаризацию файлов и проверку пар скриптов репозитория.

## Проверяемые результаты
verify.py проверяет точный SHA-256 ENT-0003/schema, корректность схемы Draft
2020-12, явно включает календарный date checker, запрещает внешние ссылки схемы
и задаёт registry без сетевого retrieval. Строгий JSON-парсер до Schema
отвергает повторные ключи, NaN/Infinity, BOM, не-UTF-8 и лишние данные.
На синтетической корректной базе отрицательные случаи изолированы по одной
существенной мутации. Отдельно проверяются текущий индекс и все JSON-решения
в catalog/approvals; неподдержанное событие не превращается в успешный тест.
Неизвестный тип решения не поддержан, а не отозван или отклонён владельцем.

Проверяются обычные артефакты и структуры метаданных ссылок на файл/каталог/
цепочку; поля зависимости links/resolved_path; ошибки дат, путей, типов,
обязательных и лишних полей. Структурно допустимая внешняя цель специально
показана как предел схемы: никакой целевой файл по этой фикстуре не читается.

## Критерии успеха и границы вывода
Успех — код 0, все 14 тестов завершены без failures/errors/skips. Ненулевой код,
ошибка импорта/чтения/схемы/окружения или прерывание не являются успехом.
Вывод unittest — журнал исполнения тестов, не утверждённый формат общего
отчёта проверки каталога. Результат относится к точным байтам кода, схемы,
lock, входного индекса и известному набору решений в момент запуска.

Тест не реализует защищённый обход файловой системы, проверку целостности всех
артефактов, доверие к решениям, транзитивный граф/ограничения, полноту ядра,
совместимость Windows или активацию. Нельзя выдавать этот код за полную процедуру
ENT-0002. Он читает доверенные локальные тестовые входы; принимать произвольное
чужое дерево как безопасный вход до реализации соответствующей границы нельзя.
Это первая реализация именно структурных испытаний, а не валидатора файлов;
поддержка физических symlink остаётся обязательной для первого такого валидатора.
При непокрытом требовании остановить соответствующий переход и обозначить пробел.

## Зависимости и лицензии
Установленные дистрибутивы сообщают SPDX: jsonschema, attrs,
jsonschema-specifications, referencing и rpds-py — MIT; typing_extensions —
PSF-2.0. Лицензионные файлы присутствуют в wheels. Это фиксация происхождения
и условий пакетов, не аудит уязвимостей, не доказательство доверия издателю
и не разрешение автоматически перепаковывать бинарники в выпуск.

Ревизия учитывает выбранную владельцем проверку изменяемого дерева.
Структурный PASS не означает атомарный снимок; точные зависимости старых
ревизий не изменены. Файловая проверка требует ожидаемого состава до чтения.
