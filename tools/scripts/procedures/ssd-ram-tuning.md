# Оптимизация под SSD и 8 ГБ ОЗУ

**Шаг 10 станционного алгоритма.** Цель — снизить износ накопителя и уложиться
в память. Выполняется при отключённой сети, после блокировки телеметрии.

Целевая станция: NVMe 256 ГБ, 8 ГБ DDR4-3200 **распаяна** — добавить память
нельзя, поэтому её объём является жёстким ограничением, а не пожеланием.

## Перед началом

| Условие | Проверка |
|---------|----------|
| Шаг 9 выполнен | [`block-telemetry.md`](block-telemetry.md) |
| Сеть отключена | Шаг 3 алгоритма |
| Свободно не менее 10–15% на системном разделе | `Get-PSDrive C` |

## Шаг 1. Пробный прогон

```powershell
& E:\tools\scripts\tune-ssd-ram.ps1 -DryRun
```

Показывает каждое действие и обратную команду, ничего не меняя.

## Шаг 2. Применение

```powershell
& E:\tools\scripts\tune-ssd-ram.ps1 -PagefileMB 4096 -MinFreePct 15
```

Скрипт делает четыре вещи и больше ничего:

| # | Действие | Почему |
|---|----------|--------|
| 1 | `powercfg /hibernate off` | Отключает гибернацию **и Fast Startup**. `hiberfil.sys` не занимает место и не пишется при каждом выключении |
| 2 | `fsutil behavior set DisableDeleteNotify 0` | TRIM обязателен для SSD; значение 1 отключает его |
| 3 | Фиксированный pagefile | `InitialSize` = `MaximumSize`, иначе система пересоздаёт файл |
| 4 | Проверка свободного места | Норма шага 10 — не менее 10–15% |

## Правило файла подкачки — не нарушать

**Файл подкачки не отключать.** При 8 ГБ распаянной памяти это прямой путь к
падениям: системе некуда вытеснять страницы, и вместо замедления получается
аварийное завершение приложений.

Ставится именно **фиксированный** размер. При автоматическом управлении Windows
пересоздаёт файл при изменении нагрузки — это лишняя запись на SSD и лишняя
фрагментация.

Размер по умолчанию 4096 МБ — половина объёма памяти. Значение подобрано как
разумный ориентир, а не измерено на целевой станции: при реальной нагрузке
может потребоваться иное.

## Кэш и временные файлы

Скрипт **не удаляет** кэш браузера и временные файлы: в них могут быть данные
текущего сеанса владельца — незакрытые вкладки, черновики, кэш авторизации.

Ограничение размера выполняется как настройка приложения:

| Что | Где | Ориентир |
|-----|-----|----------|
| Кэш Chrome | `chrome://settings` → Дополнительно, или политика `DiskCacheSize` | 256 МБ |
| Кэш Edge | `edge://settings`, или политика `DiskCacheSize` | 256 МБ |
| `%TEMP%` | Очистка вручную по согласованию с владельцем | — |

Политики браузера предпочтительнее ручной очистки: они переживают обновление
браузера и применяются ко всем профилям.

## Шаг 3. Контроль

```powershell
powercfg /a                                            # гибернация недоступна
fsutil behavior query DisableDeleteNotify              # 0
Get-CimInstance Win32_PageFileSetting | Select Name, InitialSize, MaximumSize
Get-CimInstance Win32_ComputerSystem | Select AutomaticManagedPagefile
```

То же самое проверяет
[`../validate-system.ps1`](../validate-system.ps1) — пункты 7, 8 и 9.

## Откат

Каждое действие напечатало обратную команду до изменения. Полностью:

```powershell
powercfg /hibernate on
fsutil behavior set DisableDeleteNotify 1     # только если до настройки было 1
Set-CimInstance -Query 'SELECT * FROM Win32_ComputerSystem' `
    -Property @{ AutomaticManagedPagefile = $true }
```

`DisableDeleteNotify` перед откатом **проверить**: если до настройки было 0,
возвращать 1 не нужно — это ухудшит состояние накопителя.

## Не проверено на месте

| Пункт | Что нужно |
|-------|-----------|
| `tune-ssd-ram.ps1` | PowerShell в рабочей среде отсутствует; `.sh`-половина прогнана, `.ps1` — нет |
| Размер pagefile 4096 МБ | Не измерен под реальной нагрузкой станции |
| Поведение `powercfg /hibernate off` на IoT LTSC 2024 | В некоторых редакциях гибернация отключена по умолчанию, и команда вернёт ошибку |
| Модель NVMe и его износ | `Get-PhysicalDisk \| Get-StorageReliabilityCounter` на станции |
| Политики кэша Chrome/Edge в LTSC | Доступность административных шаблонов не проверена |
