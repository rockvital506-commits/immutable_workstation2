# Валидация развёрнутой системы

Скрипт — [`../validate-system.ps1`](../validate-system.ps1) (Linux-половина —
[`../validate-system.sh`](../validate-system.sh)).

**Шаг 13 станционного алгоритма.** Без прохождения всех пунктов станция **не
сдаётся**. Это приёмка, а не диагностика: скрипт только читает и ничего не
чинит — найденное отклонение является результатом, а не поводом для
автоматической правки.

## Порядок: три прогона, а не один

Пункт 11 («настройки переживают перезагрузку») физически не проверяется за один
запуск. Поэтому:

```
прогон 1 (до перезагрузки)   validate-system.ps1 -SaveBaseline E:\reports\baseline.txt
        ↓ перезагрузка
прогон 2 (после)             validate-system.ps1 -Baseline E:\reports\baseline.txt -BackupRC <код>
        ↓
прогон 3 (приёмка)           тот же вызов; код 0 означает приёмку
```

Прогон 2 и 3 — один и тот же вызов. Разделение нужно потому, что после
перезагрузки обычно находится что-то ещё, и приёмка повторяется.

## Прогон 1. До перезагрузки

```powershell
& E:\tools\scripts\validate-system.ps1 -SaveBaseline E:\reports\baseline.txt
```

Скрипт снимет базовую линию по тем значениям, которые механизмы
самовосстановления умеют возвращать: `AllowTelemetry`, `DiagnosticData`,
состояния `DiagTrack` и `dmwappushservice`, состояния задач Application
Experience.

Код возврата будет `3` — «приёмка незавершена». Это правильно: обязательные
пункты ещё не выполнены.

Перезагрузить станцию.

## Прогон 2. После перезагрузки

```powershell
& E:\tools\scripts\validate-system.ps1 -Baseline E:\reports\baseline.txt -BackupRC 0
```

`-BackupRC` — код возврата `verify-backup`, который выполняется на шаге 14
алгоритма. Скрипт **не запускает** `verify-backup` сам: у того свои
обязательные параметры, и молчаливый запуск с неверными аргументами дал бы
ложный результат приёмки.

## Прогон 3. Проверка Центра обновления

Пункт 2 выполняется без `-DryRun` и требует включённой сети (шаг 11 алгоритма —
первое включение сети). Скрипт создаёт поисковик обновлений через COM и
выполняет сетевой запрос; ничего не устанавливается.

Если сеть ещё не включена, пункт 2 будет пропущен и приёмка останется
незавершённой с кодом `3`.

## 12 проверок

Перечень и нормы взяты из раздела 5 станционного алгоритма **без изменений**.
Это критерии приёмки, поэтому они не вынесены в профиль: менять их правкой
конфига — значит менять критерий под результат.

| # | Проверка | Норма |
|---|----------|-------|
| 1 | Сбор телеметрии отключён | `AllowTelemetry` = 0, `DiagnosticData` = 0 |
| 2 | **Центр обновления работает** | находятся и ставятся |
| 3 | Службы из блэклиста остановлены | Stopped / Disabled |
| 4 | Задачи телеметрии отключены | Disabled |
| 5 | Драйверы без проблем | 0 проблемных |
| 6 | Wi-Fi и Bluetooth работают | Connected |
| 7 | TRIM включён | `DisableDeleteNotify` = 0 |
| 8 | Гибернация выключена | недоступна |
| 9 | Файл подкачки фиксирован | фиксированный размер |
| 10 | Целостность хранилища | без ошибок |
| 11 | **Настройки переживают перезагрузку** | значения не вернулись |
| 12 | Бэкап снят и проверен | код 0 |

Нормы и команды — в разделе 5
[станционного алгоритма](../../../ventoy-partition/builds/MSI_B12M-211RU_Win11_LTSC_IoT_24H2/algorithm.md).
Бэкап проверяется [`../../backup/initial_backup/scripts/verify-backup.sh`](../../backup/initial_backup/scripts/verify-backup.sh).

### Пункт 2 обязателен

`AllowTelemetry = 0` ломает Центр обновления на части редакций, а система без
обновлений **уязвимее** системы с телеметрией. Принять станцию с неработающим
Центром обновления — значит сдать заказчику более опасную систему, чем была до
настройки.

### Пункт 11 обязателен

Часть механизмов самовосстановления возвращает значения после перезагрузки или
по расписанию. Проверка «до перезагрузки» не показывает ничего: она проверяет
состояние, которое ещё никто не пытался вернуть.

### Пункт 10 — только по явному флагу

```powershell
& E:\tools\scripts\validate-system.ps1 -Baseline E:\reports\baseline.txt -BackupRC 0 -ScanHealth
```

`DISM /Online /Cleanup-Image /ScanHealth` выполняется минуты. Без флага пункт
будет пропущен — это сделано сознательно, чтобы обычный прогон приёмки не
занимал неоправданно долго. **Перед сдачей станции выполнить с `-ScanHealth`.**

## Коды возврата

| Код | Значение | Что делать |
|-----|----------|-----------|
| 0 | Все проверки пройдены | Станция принимается |
| 1 | Ошибка, в том числе неизвестный параметр | Исправить вызов |
| 2 | Нет нужных средств | Установить недостающее |
| 3 | Обязательная проверка не выполнена | Приёмка **незавершена** — доделать пункты 2 и 11 |
| 4 | Есть проваленные проверки | Станция **не сдаётся** — исправить и повторить |

Код `3` и код `4` — разные ситуации. `3` означает «проверка не выполнялась»,
`4` — «выполнялась и провалена».

## Если проверки провалены

Скрипт не исправляет ничего. Порядок:

1. Прочитать вывод — по каждой проваленной проверке напечатана норма;
2. найти причину: применение не дошло, сработал механизм самовосстановления,
   или значение вернуло обновление;
3. если вернулось — смотреть enforcement-задачу
   (`ImmutableStation-Enforcement`) и её лог, а не повторять применение;
4. исправить и повторить прогон **заново**, включая базовую линию, если
   менялись значения из пункта 11.

## Не проверено на месте

| Пункт | Что нужно |
|-------|-----------|
| `validate-system.ps1` | PowerShell в рабочей среде отсутствует |
| COM-поиск обновлений на IoT Enterprise LTSC 2024 | `Microsoft.Update.Session` может быть ограничен в редакции |
| Наличие `pnputil` в LTSC | Проверить; при отсутствии пункт 5 будет пропущен |
| Формат вывода `powercfg /a` в русской локали | Разбор построен на поиске «Hibernate» и «недоступн»; в другой локали может не совпасть |
| Время выполнения `DISM /ScanHealth` на NVMe 256 ГБ | Не измерялось |
| Все 12 проверок на реально настроенной станции | Ни одного полного прогона приёмки не было |
