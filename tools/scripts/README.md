# scripts/ — наши универсальные скрипты

Скрипты, которые работают на **любой** станции. Станционно-специфичные (значения
под конкретную память, конкретный накопитель, конкретная политика) лежат в
сборке станции — `../../../ventoy-partition/builds/<станция>/scripts/`.

Скрипты обслуживания самой флешки и репозитория — в корневом
[`../../scripts/`](../../scripts/), а не здесь: `repo-validate`,
`check-flash`, `new-tool`, `new-iso-stub`, `csv-check`.

## Состав

| Задача | Linux | Windows | Что делает |
|--------|-------|---------|-----------|
| Аудит состояния | [`system-audit.sh`](system-audit.sh) | [`system-audit.ps1`](system-audit.ps1) | Дамп служб, задач, автозапуска, IFEO, политик, WMI-подписок, пакетов **до** изменений; повторный дамп и сравнение с первым |
| Применение блокировок | [`apply-blocking.sh`](apply-blocking.sh) | [`apply-blocking.ps1`](apply-blocking.ps1) | Применяет группы P0 → P1a → P1b → P2 → T → P3 → P5 по профилю [`apply-blocking.conf`](apply-blocking.conf) |

## Профиль: что применяется, решается в `.conf`

Перечни механизмов зашиты в скрипты — это данные из
`research/06-services-blocklist.md`, а не настройка. **Профиль станции** —
[`apply-blocking.conf`](apply-blocking.conf): какие группы применять, что
исключить, куда писать отчёт. Файл один на обе половины пары, поэтому профиль
не разъезжается между Linux и Windows. Снять комментарий — включить, поставить
— выключить; править скрипты для этого не нужно.

Неизвестный ключ профиля — **ошибка**, а не молчаливое игнорирование:
опечатка в названии не должна превращаться в «профиль не сработал».

По умолчанию `P3 = 0` и `P3_ENABLE` пуст: каждая позиция P3 ломает рабочую
функцию (печать, Hyper-V, сенсорный ввод, связь с телефоном) и включается
только под конкретный профиль заказчика. `icssvc` и `SharedAccess` внесены в
`EXCLUDE_SERVICES`: точка доступа с ноутбука — рабочий инструмент выездного
мастера.

## Без дампа применение отклоняется

`apply-blocking` отказывается работать без `-Audit`/`--audit` (код `3`). Это
не формальность: таблица «применили / откатили» в `research/06` опирается на
значения из дампа, и взять их больше неоткуда. Осознанный обход —
`-NoAudit`/`--no-audit`.

## При сбое применения откат НЕ выполняется автоматически

Каждое действие печатает обратную команду **до** изменения. При провале
выводятся: текст ошибки, обратная команда для именно этого действия и путь к
дампу. Автоматического отката нет сознательно — Win11Debloat реализовал его в
PR #613 и отклонил: откат без спроса падает по той же причине, по которой
упало применение, а принимать решение об откате за пользователя скрипт не
должен.

Провал хотя бы одного действия — код `4`, а не `0`.

## Точечные запреты (группа T) не выполняются скриптом

Подмена системного исполняемого файла wrapper'ом (механизм M8) ломает
проверку целостности (SFC, `DISM /Verify`) и не откатывается дампом. Поэтому
группа `T` в скрипте только сообщает, что включена, а сами запреты
реализуются локальной политикой — отдельным шагом через `LGPO.exe`
(`research/07-blocking-mechanisms.md`).

## Локальные политики — отдельный шаг

`apply-blocking` **не трогает GPO**. Политика применяется отдельно, и у неё
свой штатный откат: `LGPO.exe /b <путь>` делает резервную копию локальной
политики. Смешивать два механизма отката в одном скрипте — значит потерять
понимание, что именно откатывать.

## Зачем аудит обязателен до, а не после

`research/06-services-blocklist.md` формулирует прямо: исходные значения
фиксируются дампом на первом шаге, **без него откат невозможен**. Таблица
«применили / откатили» для каждого механизма опирается на значения из дампа —
например, `Set-Service X -StartupType Disabled` откатывается на
`<исходное из дампа>`, и взять его больше неоткуда.

Порядок из того же исследования:

```
1. Аудит: дамп → отчёт
2. P0 → 3. P1a → 4. P1b → 5. P2 → 6. T → 7. P3
8. Enforcement-задача (паттерн P5) + лог
9. Контроль: повторный аудит → сравнение с шагом 1 → отчёт
```

Шаги 1 и 9 — это `system-audit`: первый запуск без `-Diff`/`--diff`, последний
— с ним. Код возврата `4` означает «найдены отклонения», то есть что-то
вернулось.

## Раздел, который не участвует в сравнении

Сетевые соединения помечены `# INFO-BEGIN` / `# INFO-END` и из сравнения
исключены. Переходные состояния (`TIME-WAIT`, `FIN-WAIT-2`) меняются между
снятиями даже на неизменённой системе, и без исключения каждое сравнение
показывало бы ложные отклонения.

## Коды возврата

| Код | `system-audit` | `apply-blocking` |
|-----|----------------|------------------|
| 0 | Успех; при сравнении — отклонений нет | Успех; `-DryRun` |
| 1 | Ошибка, в том числе неизвестный параметр | Ошибка, в том числе неизвестный ключ профиля |
| 2 | Нет нужных средств | Нет прав / не запущен systemd |
| 3 | Каталог или файл недоступны | Дамп аудита не предоставлен или недоступен |
| 4 | Найдены отклонения при сравнении | Применено не всё: есть проваленные действия |

## Правила

> **Скрипт аудита ничего не меняет.** Ни при каких флагах.

> **Снимок обязателен до первого изменения.** Снятый после — для отката
> бесполезен.

> **Отклонение в сравнении — это находка, а не ошибка скрипта.** Если значения
> вернулись, значит сработал механизм самовосстановления; смотреть надо его, а
> не повторять применение.
