# tweaks/ — настройка системы и контроль отката правок

Не очистка от мусора (это [`../debloat/`](../debloat/)) и не закрепление
политиками (это [`../gpo_lock/`](../gpo_lock/)), а приведение системы к нужному
поведению и **проверка, что оно сохранилось**.

## Утилита

[`WinUtil/`](WinUtil/) — версия 26.10.07, MIT.

## Почему здесь именно контроль отката

Исследование `research/08-settings-attack-vectors.md` показало: главный вектор
атаки на сделанные настройки — не пользователь и не вредонос, а **обновления
Windows**, которые возвращают параметры к значениям по умолчанию (A1). Прямого
способа запретить откат нет. Работает только регулярная проверка состояния и
повторное применение.

Это механизм **M9** из `research/07-blocking-mechanisms.md`. WinUtil реализует
его готовым: функция `Get-WinUtilTweaksStateReport` в исходниках релиза
`26.10.07` группирует все записи из `config\tweaks.json` по категориям и для
каждой определяет текущее фактическое состояние системы. Писать свою
реализацию избыточно — правило `CONVENTIONS.md` §7.2.

## Что входит в отчёт

Состав по `config\tweaks.json` релиза `26.10.07` — **67 записей**:

| Категория | Число | Комментарий |
|-----------|-------|-------------|
| `Essential Tweaks` | 18 | Базовый набор, применяется по умолчанию |
| `Customize Preferences` | 25 | Внешний вид и поведение |
| `z__Advanced Tweaks - CAUTION` | 22 | Помечены автором как опасные |
| `Performance Plans - NOT FOR LAPTOPS` | 2 | **Не применять**: MSI Modern 15 — ноутбук |

Из 67 записей 50 описаны через реестр и 2 через службы. Остальные — типа
`Combobox` и действия-кнопки: у них нет определяемого состояния, и в отчёт они
попадают отдельным списком «не оценивается». Это не ошибка.

## Порядок

1. Применить основной слой — Win11Debloat.
2. Запустить WinUtil, получить отчёт о состоянии.
3. Экспортировать конфигурацию — она пригодится на других станциях.
4. Через некоторое время, особенно после обновлений, запустить повторно и
   сравнить отчёт. Расхождения — это и есть откат.

Режим `Updates → security` у WinUtil закрывает большую часть задачи по
[`../updates/`](../updates/), но **удаляет** ключ `NoAutoRebootWithLoggedOnUsers`,
который ставит Win11Debloat. Порядок применения — в индексе группы.

## Правила

> Отчёт о состоянии снимать до и после каждого крупного обновления. Без этого
> «настройки слетели» остаётся догадкой.

> Категорию `Performance Plans` на этой станции не применять.

> Экспорт конфигурации хранить в каталоге станционной сборки, а не только на
> флешке: конфигурация — часть эталона станции.
