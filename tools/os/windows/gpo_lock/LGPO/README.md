# LGPO/ — применение локальной политики без gpedit.msc

## Назначение

`LGPO.exe` — утилита Microsoft из Security Compliance Toolkit. Применяет
локальную групповую политику из файлов и **делает её резервную копию**.

В проекте решает две задачи:

1. **Перенос готовой политики между станциями.** При «зоопарке» своего железа нужен один
   и тот же набор запретов на каждом ПК, а не ручная настройка через
   `gpedit.msc` на каждой станции.
2. **Штатный откат слоя GPO.** `LGPO.exe /b <каталог>` сохраняет текущую
   локальную политику до изменения. Это единственный из применяемых в проекте
   механизмов, у которого обратная операция предусмотрена самой утилитой.

## Почему политика применяется отдельным шагом

`apply-blocking` намеренно **не трогает** локальные политики. Причина — разный
механизм отката:

| Слой | Чем откатывается |
|------|------------------|
| Реестр, службы, задачи | Дамп `system-audit` + обратная команда из вывода |
| Локальная политика | Резервная копия `LGPO.exe /b` |

Смешать их в одном скрипте — значит потерять понимание, что именно откатывать
при частичном сбое.

## Почему одной политики мало

См. [`../README.md`](../README.md): локальную политику можно сбросить правами
локального администратора, и это штатный, публично документированный способ.
Поэтому политика — последний слой, а не единственный, и её применение не
отменяет ни блокировку служб, ни enforcement-задачу.

## Лицензия

`LGPO.exe` входит в **Microsoft Security Compliance Toolkit 1.0**, страница
загрузки `microsoft.com/en-us/download/details.aspx?id=55319`. По этой
странице: `LGPO.zip`, версия **1.0**, объём **519.2 КБ**, дата публикации
**2026-10-05**.

Набор распространяется бесплатно; отдельного текста лицензионного соглашения
для `LGPO.exe` на странице загрузки нет, он входит в скачиваемый архив.
Прочитать его из рабочей среды нельзя: `microsoft.com` вне белого списка.

**Номер сборки утилиты — 3.0.2004.13001.** Это строка из собственного вывода
`LGPO.exe`, приведённая в трёх независимых источниках; версия 1.0 на странице
загрузки относится к набору Security Compliance Toolkit, а не к файлу. Номер
внесён в `manifest.csv`, находка N2 закрыта.

Ожидаемая контрольная сумма архива `LGPO.zip` внесена как `PENDING`-замена —
`cb7159d1…47cc55` — с обязательной пометкой: источник сторонний
(prefetch-блок BigFix от 2024-11-11), Microsoft своих сумм не публикует,
поэтому сумма служит ориентиром, а не доказательством. Относится к архиву, а не
к распакованному `.exe`. Строка первая из утилит выполнила три условия
перехода в `present` из `CONVENTIONS.md` §4 — заглушка, известный URL и
ожидаемая сумма с пометкой об источнике.
