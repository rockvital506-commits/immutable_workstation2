# Офлайн-обновления Windows — процедура

**Решение заказчика от 2026-10-14: каталог обновлений на флешке не
заводится.** Вместо него — эта процедура: что скачать, как назвать, как
проверить и как поставить.

Обоснование — `../../../../research/13-offline-updates.md`. Коротко:
офлайн-пакет свежего накопительного занимает несколько гигабайт, каждое
накопительное вытесняет предыдущее, выходят они ежемесячно. Хранимый каталог
устаревает быстрее, чем используется, и отнимает место у пака драйверов.

## Когда это нужно

- На станции нет интернета, а обновление поставить надо.
- Центр обновления на станции сломан, и чинить его в этот выезд некогда.
- Нужно поднять образ установщика до актуальной сборки перед установкой.

Если интернет на станции есть — обновления придут сами. Политика Центра
обновления описана в этом же каталоге, в [`README.md`](README.md).

## Шаг 1. Определить, что именно нужно

| Что | Где посмотреть |
|-----|----------------|
| Редакция и сборка станции | `winver` на станции |
| Уже установленные обновления | `Параметры → Центр обновления → Журнал обновлений` |
| Номер нужного KB | `https://www.microsoft.com/ru-ru/windows/release-health` |
| Текущий servicing stack | `DISM /Online /Get-Packages` или `Get-WindowsPackage -Online` |

**SSU отдельно искать не нужно.** Для Windows 10 версии 2004 и новее отдельные
пакеты SSU не выпускаются с марта 2021 года — servicing stack встроен в LCU.
Целевая станция (Win11 IoT Enterprise LTSC 2024, 24H2, build 26100) — этот
случай.

## Шаг 2. Скачать

Источник единственный официальный — **Microsoft Update Catalog**:

```
https://www.catalog.update.microsoft.com/Home.aspx
```

Искать по номеру KB **без пробела**: `KB5074109`, не `KB 5074109`.

Что скачать:

- **все** файлы `.msu` и `.cab`, которые каталог отдаёт для этого KB;
- точное совпадение по редакции, сборке и разрядности — несовпадение даёт
  «not applicable» при установке, и это самая частая ошибка;
- для x64-станции — только x64.

Каталог работает в Edge, Chrome и Firefox; старое ограничение «только
Internet Explorer и ActiveX» снято.

## Шаг 3. Назвать и положить

Имя файла оставить как скачалось — в нём есть KB и разрядность, по нему пакет
найдётся позже. Хранить в каталоге с меткой месяца:

```
Tools:\os\windows\updates\offline\2026-10\
├── Windows11.0-KB5074109-x64_<хэш>.msu
└── manifest.sha256.csv
```

## Шаг 4. Записать манифест

Как и для остальных бэкапов проекта — с SHA256. В PowerShell:

```powershell
Get-ChildItem "*.msu","*.cab" |
    Get-FileHash -Algorithm SHA256 |
    ForEach-Object { "$($_.Hash.ToLower()),$($_.Path | Split-Path -Leaf)" } |
    Set-Content -Encoding utf8 manifest.sha256.csv
```

Без манифеста пакет непроверяем: через месяц невозможно сказать, тот ли это
файл и не повреждён ли он.

## Шаг 5. Установить

**Все пакеты одного KB положить в один каталог** и указать DISM на каталог, а
не на файл — тогда зависимости разрешатся автоматически. Это рекомендованный
Microsoft способ.

На работающей системе:

```cmd
DISM /Online /Add-Package /PackagePath:C:\Packages
```

```powershell
Add-WindowsPackage -Online -PackagePath "C:\Packages"
```

В образ установщика:

```cmd
DISM /Mount-Image /ImageFile:D:\sources\install.wim /Index:1 /MountDir:E:\mount
DISM /Image:E:\mount /Add-Package /PackagePath:C:\Packages
DISM /Unmount-Image /MountDir:E:\mount /Commit
```

Если пакеты ставятся по отдельности, а не каталогом, **порядок обязателен:
сначала SSU, потом LCU**. MSU-пакет делает это сам.

Проверка после установки: `winver` и `Параметры → Центр обновления → Журнал`.

## Порядок при раздельной установке

```cmd
DISM /Online /Add-Package /PackagePath:C:\Packages\SSU.msu
DISM /Online /Add-Package /PackagePath:C:\Packages\LCU.msu
```

Перезагрузка — один раз, после LCU.

## Чего делать нельзя

> **Не рассчитывать на откат пакета, содержащего SSU.** SSU не удаляется
> ключом `/uninstall`. Единственный надёжный возврат — эталонный образ,
> который в алгоритме станции и так снимается до изменений.

> **Изменения WinRE от SafeOS Dynamic Update необратимы** для образа.

> **Не ставить пакет, не сверив редакцию и сборку.** «Not applicable» — самая
> частая ошибка, и она не всегда очевидна: DISM может просто пропустить пакет.

> **Не ставить обновления до пост-теста Центра обновления.** Требование
> проекта: `AllowTelemetry = 0` не должно ломать Центр обновления, и
> проверяется это до того, как обновления поедут. См. [`README.md`](README.md).

> **Не оставлять станцию на паузе без срока.** Через несколько месяцев
> обновления придут одним пакетом и откатят часть настроек разом.

## Манифест

| Поле | Значение |
|------|----------|
| Каталог на флешке | `Tools:\os\windows\updates\offline\<ГГГГ-ММ>\` |
| Файлы в git | **не хранятся** — только эта инструкция |
| Периодичность обновления | перед выездом, если ожидается работа без интернета |
| Сколько хранить | один-два последних месяца, старое удалять |

## Не проверено на месте

| Пункт | Что нужно |
|-------|-----------|
| Условия хранения скачанных пакетов при коммерческом использовании | `catalog.update.microsoft.com` недоступен из рабочей среды |
| Какие накопительные применимы к IoT Enterprise LTSC 2024 | У LTSC-редакций набор обновлений отличается от потребительских |
| Наличие `DISM` в WinPE Strelec | Проверить в выезде |
| Поведение `Add-Package` на образе IoT LTSC 2024 | Пробная интеграция на тестовой машине |
| Номера KB из этого документа | В документе их нет намеренно — они устаревают за месяц |
