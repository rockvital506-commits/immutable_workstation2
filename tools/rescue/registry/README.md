# registry/ — офлайн-правка реестра

## Задача

Править кусты реестра системы, которая не загружается, — без её запуска.
Типовые причины: испорченный профиль, драйвер с отказом на старте, политика,
из-за которой система не даёт войти, неверные параметры загрузки.

## Что уже есть в Strelec

| Утилита | Когда применять |
|---------|-----------------|
| `Registry Editor PE` | Основной инструмент: открывает кусты офлайн, интерфейс привычный |
| `regedit` + ручная загрузка кустов | Когда нужна полная предсказуемость и скриптуемость |
| `Dism++ 10.1.1002.1` | Правки, связанные с образами и компонентами |
| `ShowKeyPlus 1.1.18.0` | Ключ продукта из реестра и BIOS |
| `OemKey` | OEM-ключ из прошивки |
| `Recover Keys` | Лицензии установленного софта |
| `WinHex` / `CIHexViewer 2.0` | Когда реестр повреждён настолько, что regedit его не открывает |

## Портативных дополнений нет

Правка реестра из живой ОС бессмысленна: там реестр и так доступен обычным
`regedit`. Офлайн-правка нужна именно из среды вне ОС, то есть из WinPE, где
инструменты уже есть.

## Ручной способ через reg load

Надёжнее любого GUI, потому что видно, что именно происходит:

```cmd
:: 1. Примонтировать куст
reg load HKLM\OFFLINE D:\Windows\System32\config\SYSTEM

:: 2. Править
reg add "HKLM\OFFLINE\ControlSet001\Services\<служба>" /v Start /t REG_DWORD /d 4 /f

:: 3. Обязательно выгрузить — иначе куст останется заблокированным
reg unload HKLM\OFFLINE
```

Кусты лежат в `<буква>:\Windows\System32\config\`:

| Файл | Ветка в загруженной системе |
|------|-----------------------------|
| `SYSTEM` | `HKLM\SYSTEM` |
| `SOFTWARE` | `HKLM\SOFTWARE` |
| `SECURITY` | `HKLM\SECURITY` |
| `DEFAULT` | `HKEY_USERS\.DEFAULT` |
| `NTUSER.DAT` в профиле | `HKEY_USERS\<SID>` |

## Типовые сценарии

| Задача | Куст | Что править |
|--------|------|-------------|
| Отключить драйвер, из-за которого система не стартует | `SYSTEM` | `ControlSet001\Services\<имя>\Start = 4` |
| Включить встроенного администратора | `SYSTEM` | `Setup\Type` — см. ниже |
| Убрать программу из автозагрузки | `SOFTWARE` | `Microsoft\Windows\CurrentVersion\Run` |
| Отменить политику, блокирующую вход | `SOFTWARE` | `Policies\Microsoft\Windows\...` |
| Достать ключ Windows | `SOFTWARE` | `Microsoft\Windows NT\CurrentVersion\DigitalProductId` |
| Войти в систему как встроенный администратор при установке | `SYSTEM` | `Setup\CmdLine` = `cmd.exe`, `Setup\Type` = `MiniNT` |

Последний приём даёт командную строку при следующей загрузке; после работ
**обязательно** вернуть `Setup\Type` в пустое значение, иначе система будет
грузиться в режиме OOBE.

## Правила

> **`reg unload` обязателен.** Незакрытый куст остаётся заблокированным, и
> система может не загрузиться или потерять правки.

> **Выгрузить куст до перезагрузки.** Даже если кажется, что всё сохранено.

> **Сохранить копию куста перед правкой.** Файл куста просто копируется:
> `copy SYSTEM SYSTEM.bak`.

> **Править `ControlSet001`, а не `CurrentControlSet`.** Вне загруженной
> системы `CurrentControlSet` не существует; какой из наборов активный, видно
> в `SYSTEM\Select\Current`.

> Ошибка в `SYSTEM` делает систему незагружаемой быстрее, чем любая другая.
> Если правка не обязательна — не делать её.
