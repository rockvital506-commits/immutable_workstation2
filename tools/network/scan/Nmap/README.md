# Nmap

## Назначение

Обнаружение узлов в сети, открытых портов, версий служб и типа устройства.
Отвечает на вопросы «что вообще есть в этой сети» и «что на нём открыто
наружу».

## Когда применять

- Инвентаризация сети владельца: какие устройства реально живут в сегменте.
- Проверка роутера: какие порты торчат наружу.
- Поиск устройства с неизвестным адресом.
- Диагностика «не работает сетевая папка или принтер» — открыт ли нужный порт.
- Проверка, что после настройки межсетевого экрана закрылось то, что должно
  было закрыться.

Комплект Nmap включает не только сам сканер, но и `Zenmap` (графический
интерфейс), `Ncat` (передача данных и отладка), `Ndiff` (сравнение результатов
сканирования) и `Nping` (генерация пакетов).

## Запуск

```cmd
nmap -sn 192.168.1.0/24
```

- Требуются права администратора: **да** для SYN-сканирования, определения ОС и
  UDP; **нет** для TCP-connect
- Работает из-под WinPE: **не проверено**. Большинство режимов требует
  драйвера `Npcap`; TCP-connect (`-sT`, `-p порт`) теоретически обходится
  без него, но на месте это не подтверждено
- Работает с флешки без установки: **нет**, это инсталлятор
- Требует .NET / VC++ Redist: **нет**, но требует `Npcap`

## Ключи и типовые сценарии

| Задача | Команда |
|--------|---------|
| Кто живой в сегменте | `nmap -sn 192.168.1.0/24` |
| Открытые TCP-порты узла | `nmap -sT 192.168.1.1` |
| Быстрое сканирование частых портов | `nmap -F 192.168.1.1` |
| Все 65536 портов диапазона 0-65535 | `nmap -p- 192.168.1.1` |
| Версии служб | `nmap -sV 192.168.1.1` |
| Определение ОС | `nmap -O 192.168.1.1` |
| UDP-порты | `nmap -sU 192.168.1.1` |
| Конкретный порт | `nmap -p 445 192.168.1.0/24` |
| Список целей из файла | `nmap -iL hosts.txt` |
| Результат в файл | `nmap -oN report.txt 192.168.1.0/24` |
| Результат в XML | `nmap -oX report.xml 192.168.1.0/24` |
| Трассировка до узла | `nmap --traceroute 8.8.8.8` |

## Результаты и как их читать

| Состояние порта | Что означает |
|-----------------|--------------|
| `open` | Служба слушает |
| `closed` | Узел ответил отказом — узел есть, службы нет |
| `filtered` | Пакеты не доходят, вероятно межсетевой экран |
| `open|filtered` | Обычно UDP: ответа нет, но и отказа нет |

Для отчёта владельцу достаточно `-sn` плюс список открытых портов на роутере.
Полное сканирование с `-sV -O` даёт много текста и редко нужно целиком.

## Риски и предупреждения

> **Сканировать только с разрешения владельца сети.** Это первое правило, и оно
> не формальность: сканирование чужой сети может быть расценено как попытка
> несанкционированного доступа. Разрешение фиксировать в заявке.

> Требует драйвер `Npcap`. Это драйвер уровня ядра, установка на станцию
> владельца — отдельное действие с его согласия.

> Активное сканирование видно в журналах межсетевого экрана и может поднять
> тревогу у службы безопасности владельца. Предупреждать заранее.

> Полное сканирование `-p-` по всему сегменту — это тысячи пакетов на каждое
> устройство. На работающей сети с IoT-устройствами начинать с `-F`.

> Лицензия Nmap — **Nmap Public Source License** (NPSL 0.95), не
> OSI-сертифицированная. Коммерческое использование концевым пользователем
> бесплатное: «Nmap is generally free for end users to download and use
> themselves, including commercial use» (`nmap_winconfig.h`, `nmap/nmap`).

> **ОГРАНИЧЕНИЕ, которое нас касается.** Официальные сборки Nmap для Windows
> содержат драйвер `Npcap`, а он под собственной лицензией, запрещающей
> распространение без отдельного разрешения: «the official Nmap Windows builds
> which include Npcap **may not be redistributed without special permission**»
> (`nmap.org/book/man-legal.html`, раздел 10 NPSL).
>
> Мы положили на флешку `nmap-7.992.zip` с официальной Windows-сборкой
> внутри. Прежний вывод был таким: раз флешка выезжает к заказчикам, речь о
> распространении, и формулировка «мы ничего не распространяем» неверна.
>
> **С 2026-10-16 профиль некоммерческий**, и основание риска отпало: флешка
> личная, копия никому не передаётся, редистрибуции нет
> (`research/25-profile-change.md`, категория B). Запрет раздела 10 NPSL при
> этом не отменён — он вернётся, если флешка будет передана или выложена
> публично. К находке N18 добавлена та же пометка.
>
> **Решение владельца от 2026-10-15: хранить нераспакованным архивом.**
> Файл на флешке — архив `nmap-7.992.zip`, содержащий `nmap-7.992-setup.exe`;
> распаковка и установка — на месте, на машине, где утилита будет запущена.
> Основание — оговорка NPSL: «Including Nmap with other software in compressed
> or archival form does not trigger this provision, provided appropriate open
> source decompression or de-archiving software is widely available for no
> charge».
>
> **Риск принят осознанно и записан** (`research/23-license-scope.md`, N18):
> раздел 10 NPSL про официальные Windows-сборки сформулирован безусловнее, чем
> оговорка про архивы, поэтому однозначного вывода о правомерности нет.
> Альтернативы, от которых отказались: качать на месте (нужен интернет на
> работе), замена (теряем `-sV` и NSE), OEM-лицензия (платно).

## Версия и источник

| Поле | Значение |
|------|----------|
| Версия | 7.992 — **сверена с первоисточником** |
| Дата релиза | 2026-10-13 |
| Дата проверки версии | 2026-10-21 |
| Официальный сайт | https://nmap.org/ |
| Прямая ссылка на файл | https://nmap.org/dist/nmap-7.992-setup.exe |
| SHA256 инсталлятора | `7d99ee28b2eae1a90917bb45afc42c1e900a271e7f1bbe1234cf266a819bacc8` |
| SHA256 нашего архива | `PENDING` — вычисляется после упаковки |
| Размер | инсталлятор 36 МБ |
| Лицензия | Nmap Public Source License (NPSL), с версии 7.90 |

**Версия сверена с первоисточником напрямую 2026-10-21**: `nmap.org` открылся
из рабочей среды. Каталог `nmap.org/dist/` заявляет «The latest Nmap release
is version 7.992», файл `nmap-7.992-setup.exe` датирован 2026-10-13 и
занимает 36 МБ. Прежде версия подтверждалась косвенно — поисковой выдачей и
тегом в зеркале, — потому что сайт вендора был недоступен; теперь в этом нет
нужды.

**Релиза с ассетами в GitHub-зеркале по-прежнему нет** — проверено через API
2026-10-21: запросы `releases/latest` и `releases/tags/v7.992` возвращают
`Not Found`, хотя сам тег `v7.992` в списке тегов есть. Ассеты релизов
зеркало не публикует, поэтому источником файла остаётся `nmap.org`, а ссылка
в `manifest.csv` ведёт прямо на `dist/`, а не на страницу загрузки.

**Про SHA256.** Вендор публикует суммы в
`nmap.org/dist/sigs/nmap-7.992-setup.exe.digest.txt` — MD5, SHA1, RMD160,
SHA224, SHA256, SHA384, SHA512 — и отсоединённую подпись PGP. SHA256
инсталлятора внесён в паспорт выше.

Это сумма **инсталлятора, а не нашего архива**: архив `.zip` собираем мы
сами, в каталоге вендора его нет, и его сумма не опубликована нигде. Она
вычисляется после упаковки, поэтому строка `manifest.csv` остаётся `planned`
с `sha256 = PENDING` (§4) — не потому, что источник суммы не найден, а
потому, что самого архива на носителе ещё нет.

Порядок сверки обязателен: сначала инсталлятор против суммы вендора, потом
упаковка, потом сумма архива. Обратный порядок доказывает только целостность
при переносе, но не подлинность содержимого.

Драйвер `Npcap` — отдельно, свежий `npcap-1.89.exe` с `npcap.com`.
