# Nmap

## Назначение

Обнаружение узлов в сети, открытых портов, версий служб и типа устройства.
Отвечает на вопросы «что вообще есть в этой сети» и «что на нём открыто
наружу».

## Когда применять

- Инвентаризация сети заказчика: какие устройства реально живут в сегменте.
- Проверка роутера: какие порты торчат наружу.
- Поиск устройства с неизвестным адресом.
- Диагностика «не работает сетевая папка или принтер» — открыт ли нужный порт.
- Проверка, что после настройки межсетевого экрана закрылось то, что должно
  было закрыться.

Комплект Nmap включает не только сам сканер, но и `Zenmap` (графический
интерфейс), `Ncat` (передача данных и отладка), `Ndiff` (сравнение результатов
сканирования) и `Nping` (генерация пакетов).

## Запуск

```cmd
nmap -sn 192.168.1.0/24
```

- Требуются права администратора: **да** для SYN-сканирования, определения ОС и
  UDP; **нет** для TCP-connect
- Работает из-под WinPE: **требует установки драйвера Npcap**
- Работает с флешки без установки: **нет**, это инсталлятор
- Требует .NET / VC++ Redist: **нет**, но требует `Npcap`

## Ключи и типовые сценарии

| Задача | Команда |
|--------|---------|
| Кто живой в сегменте | `nmap -sn 192.168.1.0/24` |
| Открытые TCP-порты узла | `nmap -sT 192.168.1.1` |
| Быстрое сканирование частых портов | `nmap -F 192.168.1.1` |
| Все 65535 портов | `nmap -p- 192.168.1.1` |
| Версии служб | `nmap -sV 192.168.1.1` |
| Определение ОС | `nmap -O 192.168.1.1` |
| UDP-порты | `nmap -sU 192.168.1.1` |
| Конкретный порт | `nmap -p 445 192.168.1.0/24` |
| Список целей из файла | `nmap -iL hosts.txt` |
| Результат в файл | `nmap -oN report.txt 192.168.1.0/24` |
| Результат в XML | `nmap -oX report.xml 192.168.1.0/24` |
| Трассировка до узла | `nmap --traceroute 8.8.8.8` |

## Результаты и как их читать

| Состояние порта | Что означает |
|-----------------|--------------|
| `open` | Служба слушает |
| `closed` | Узел ответил отказом — узел есть, службы нет |
| `filtered` | Пакеты не доходят, вероятно межсетевой экран |
| `open|filtered` | Обычно UDP: ответа нет, но и отказа нет |

Для отчёта заказчику достаточно `-sn` плюс список открытых портов на роутере.
Полное сканирование с `-sV -O` даёт много текста и редко нужно целиком.

## Риски и предупреждения

> **Сканировать только с разрешения владельца сети.** Это первое правило, и оно
> не формальность: сканирование чужой сети может быть расценено как попытка
> несанкционированного доступа. Разрешение фиксировать в заявке.

> Требует драйвер `Npcap`. Это драйвер уровня ядра, установка на станцию
> заказчика — отдельное действие с его согласия.

> Активное сканирование видно в журналах межсетевого экрана и может поднять
> тревогу у службы безопасности заказчика. Предупреждать заранее.

> Полное сканирование `-p-` по всему сегменту — это тысячи пакетов на каждое
> устройство. На работающей сети с IoT-устройствами начинать с `-F`.

> Лицензия Nmap — **Nmap Public Source License**, не OSI-одобренная.
> Коммерческое использование бесплатное, но при распространении вместе со
> своим продуктом есть ограничения. Мы используем утилиту как есть и ничего не
> распространяем, поэтому ограничения нас не касаются.

**Версия не сверена с первоисточником напрямую**: `nmap.org` недоступен из
рабочей среды (`http=000`). Версия 7.991 и имя файла `nmap-7.991-setup.exe`
подтверждены двумя независимыми путями: поисковой выдачей по официальной
странице загрузки и тегом `v7.991` в зеркале `nmap/nmap` на GitHub.

**Релиза с ассетами в GitHub-зеркале нет** — проверено через API: запросы
`releases/latest` и `releases/tags/v7.991` возвращают `Not Found`. Поэтому
ссылка в `manifest.csv` ведёт на страницу загрузки, а не на конкретный файл.

Драйвер `Npcap` — отдельно, свежий `npcap-1.89.exe` с `npcap.com`.
