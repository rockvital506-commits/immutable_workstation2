# iperf3

## Назначение

Замер фактической пропускной способности канала между двумя узлами. Отвечает
на вопрос «сколько мегабит реально проходит», а не «сколько обещано в
тарифе».

## Когда применять

- Заказчик жалуется на медленный интернет, надо отделить его сеть от канала
  провайдера.
- Проверка Wi-Fi: сравнение замера по кабелю и по воздуху на том же месте.
- Проверка нового кабеля, свитча, порта роутера.
- Проверка локальной сети между двумя станциями или станцией и NAS.
- Проверка влияния помех: замер в разных точках помещения.

## Запуск

Сервер на второй стороне, клиент на измеряемой:

```cmd
:: на принимающей стороне
iperf3.exe -s

:: на измеряемой стороне
iperf3.exe -c 192.168.1.50
```

- Требуются права администратора: **нет**
- Работает из-под WinPE: **да**
- Работает с флешки без установки: **да**, портативный ZIP
- Требует .NET / VC++ Redist: **нет** в статической сборке

## Ключи и типовые сценарии

| Задача | Команда |
|--------|---------|
| Сервер | `iperf3 -s` |
| Сервер на определённом порту | `iperf3 -s -p 5201` |
| Клиент | `iperf3 -c адрес` |
| Замер 30 секунд | `iperf3 -c адрес -t 30` |
| Замер в обратную сторону | `iperf3 -c адрес -R` |
| Несколько потоков | `iperf3 -c адрес -P 4` |
| Замер UDP и потерь | `iperf3 -c адрес -u -b 100M` |
| Интервал между отчётами | `iperf3 -c адрес -i 1` |
| Только сводка | `iperf3 -c адрес -O 5` |
| Вывод в JSON для отчёта | `iperf3 -c адрес -J` |
| Ограничение скорости | `iperf3 -c адрес -b 50M` |

## Результаты и как их читать

Клиент печатает таблицу по интервалам и строку `[SUM]` с итогом. Смотреть:

| Поле | Что означает |
|------|--------------|
| `Bitrate` | Пропускная способность. Сравнивать с тарифом и с номиналом канала |
| `Retr` | Повторы передачи TCP. Много повторов — потери или перегрузка |
| `Jitter` (в UDP) | Разброс задержки. Важно для звонков и видео |
| `Lost/Total` (в UDP) | Доля потерянных пакетов |

Норма для гигабитной локальной сети по кабелю — порядка 940 Мбит/с. Всё, что
существенно ниже при замере по кабелю, — проблема кабеля, порта или свитча, а
не провайдера.

`-J` даёт JSON: его удобно складывать в отчёт по выезду и сравнивать замеры до
и после.

## Риски и предупреждения

> Для замера нужны **две стороны**. На одной машине измерить канал нельзя.
> Сервер поднимается на второй станции, на NAS или на Live Mint с флешки.

> Замер через интернет упирается в тариф, а не в сеть. Чтобы отделить сеть
> заказчика от канала, замерять сначала внутри локальной сети, потом наружу.

> Замер по Wi-Fi зависит от расстояния, помех и диапазона. Фиксировать в
> отчёте, где именно стояла станция и на каком диапазоне.

> `-P` с большим числом потоков нагружает канал. На работающей сети заказчика
> начинать с одного потока.
