# wifi/ — Wi-Fi: эфир и точка доступа

Две разные задачи, и у них разные инструменты: **посмотреть эфир** и
**поднять свою сеть**.

## Состав

| Утилита | Задача | Статус |
|---------|--------|--------|
| [`WifiInfoView/`](WifiInfoView/) | Пассивное сканирование эфира: каналы, уровень сигнала, соседи | внедрена |
| [`MyPublicWifi/`](MyPublicWifi/) | Точка доступа там, где встроенный хот-спот не запускается | **внедрена условно**, лицензия не проверена |

## Сначала встроенные средства

До любой сторонней утилиты — то, что уже есть в Windows:

| Задача | Команда |
|--------|---------|
| Текущее подключение: канал, скорость, сигнал | `netsh wlan show interfaces` |
| Все видимые сети с BSSID | `netsh wlan show networks mode=bssid` |
| Возможности адаптера и поддержка hosted network | `netsh wlan show drivers` |
| Сохранённые профили | `netsh wlan show profiles` |
| Ключ сохранённой сети | `netsh wlan show profile name=SSID key=clear` |
| Скрытые адаптеры, включая виртуальный хот-спот | `Get-NetAdapter -IncludeHidden` |
| Сброс стека Wi-Fi | `netsh winsock reset` + перезагрузка |

## Выбор канала

Основная практическая задача. Порядок:

1. `WifiInfoView` в режиме сводки по каналам.
2. Смотреть **занятость канала**, а не число сетей: одна сеть на 20 МГц мешает
   меньше, чем три на 40 МГц.
3. Для 2.4 ГГц использовать только каналы **1, 6, 11** — остальные
   перекрываются с соседними.
4. Если сетей много и эфир забит — переводить на 5 ГГц, а не искать свободный
   канал в 2.4 ГГц.
5. После смены канала проверить скорость по [`../speed/`](../speed/) на том же
   месте.

## Точка доступа

**Встроенный «Мобильный хот-спот» Windows использовать всегда, когда есть
интернет.** Он не требует установки, даёт WPA2, показывает число клиентов
(максимум 8) и позволяет выбрать диапазон.

Критическое ограничение: **без подключения к интернету он не запускается.**
Windows умеет удерживать уже работающую точку при пропадании сети, но не умеет
запускать её без сети. Подтверждено тремя независимыми ответами на Microsoft
Q&A. Подробно — `research/09-mypublicwifi-rustdesk.md`, B3.

Старый способ `netsh wlan set hostednetwork` не замена: нужен
`Hosted network supported: Yes` в выводе `netsh wlan show drivers`, а на
современных адаптерах, включая Intel AX211, его обычно нет.

`MyPublicWifi` закрывает именно этот провал. Но: версия, подпись и лицензия по
первоисточнику **не проверены**, после установки нужна перезагрузка, и
**URL-журналирование включать запрещено**.

## Сценарий связки с удалённым доступом

Автономная работа без интернета заказчика:

1. `MyPublicWifi` поднимает изолированную точку доступа.
2. Устройства подключаются к ней.
3. `RustDesk` работает внутри этой сети — модуль `src/lan.rs` даёт обнаружение
   узлов **без сервера согласования**.
4. `RustDesk --port-forward` пробрасывает порты роутера или NAS для проверки.

Ни публичный сервер RustDesk, ни интернет заказчика не нужны. Полное описание —
`research/09-mypublicwifi-rustdesk.md`, раздел C.

## Правила

> Не менять настройки роутера заказчика, не записав исходные: SSID, пароль,
> канал, ширина канала, режим. Иначе восстановить «как было» нечем.

> Ключ сохранённой сети через `key=clear` — это чужой пароль. Не сохранять и не
> переносить.

> Два средства создания виртуальной точки доступа одновременно не работают:
> конфликт выделения адресов. Перед запуском одного отключить другое.
