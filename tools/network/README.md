## Ключевой сценарий: работа без интернета заказчика

Сеть у клиента недетерминирована, и часто её нет совсем. Под этот случай есть
автономная связка:

1. [`wifi/MyPublicWifi`](wifi/MyPublicWifi/) поднимает изолированную точку
   доступа там, где встроенный хот-спот Windows не запускается.
2. Устройства подключаются к ней.
3. [`remote/RustDesk`](remote/RustDesk/) работает внутри этой сети — модуль
   `src/lan.rs` даёт обнаружение узлов **без сервера согласования**.
4. `RustDesk --port-forward` пробрасывает порты роутера или NAS заказчика.

Ни интернет заказчика, ни публичный сервер RustDesk не нужны. Обоснование —
`research/09-mypublicwifi-rustdesk.md`, раздел C.

## Правило

На раздел `Tools` кладётся только то, чего в Strelec нет, либо то, что должно
запускаться **из живой ОС** без перезагрузки в WinPE.

Второй критерий важнее первого: флешка нужна не для хранения копий, а для
того, чтобы не перезагружать станцию заказчика там, где это не нужно.

## Порядок диагностики

Порядок важнее инструмента. Пропуск шага даёт неверный вывод.

1. Своя машина: `ipconfig /all`.
2. Шлюз: `ping` на адрес шлюза.
3. Наружу по адресу: `ping 8.8.8.8`.
4. Наружу по имени: `ping ya.ru`.
5. Скорость: [`speed/`](speed/).
6. Что открыто: [`scan/`](scan/).
7. Что в эфире, если это Wi-Fi: [`wifi/`](wifi/).
8. Разбор по пакетам, если всё выше не объяснило: [`capture/`](capture/).

## Правила группы

> Не менять настройки сети станции заказчика, не сняв исходные `ipconfig /all`
> и `route print` в файл.

> Сканирование и перехват трафика — только с разрешения владельца сети,
> зафиксированного в заявке.

> Несанкционированный постоянный доступ к станции заказчика не устанавливать.
> Только по договору, с записью о том, что поставлено и как снимается.

> Версии утилит закреплены в `/manifest.csv`. Четыре из шести сверены с
> первоисточником через API GitHub; версии `Nmap`, `Wireshark`, `WifiInfoView`
> и `MyPublicWifi` — нет, сайты вендоров недоступны из рабочей среды.
