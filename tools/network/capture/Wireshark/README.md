# Wireshark

## Назначение

Разбор дампов сетевого трафика. Нужен, когда «не работает» уже локализовано до
протокола и надо посмотреть, что именно происходит в обмене.

На флешку кладётся **портативная сборка**, которая не ставит драйвер. Её
задача — открывать и разбирать файлы `.pcapng`, а не перехватывать трафик на
станции заказчика.

## Когда применять

- Есть готовый дамп, снятый на роутере или другой машине, и его надо разобрать.
- Не работает конкретный протокол: DHCP, DNS, SMB, NTP, VPN.
- Надо увидеть, кто в сети рассылает широковещательные пакеты.
- Надо подтвердить, что устройство действительно обращается наружу, — по
  фактическим пакетам, а не по догадке.

## Запуск

`paf.exe` запускается один раз и распаковывает портативный каталог. Дальше
запускается уже он.

- Требуются права администратора: **нет** для разбора файлов, **да** для живого
  перехвата
- Работает из-под WinPE: **да** для разбора файлов
- Работает с флешки без установки: **да**
- Требует .NET / VC++ Redist: **да**, Visual C++ Redistributable x64

## Ключи и типовые сценарии

Основная работа идёт в интерфейсе через фильтры отображения.

| Задача | Фильтр |
|--------|--------|
| Только DHCP | `bootp` |
| Только DNS | `dns` |
| Обращения к конкретному адресу | `ip.addr == 192.168.1.1` |
| Трафик конкретного узла | `eth.addr == aa:bb:cc:dd:ee:ff` |
| Только TCP | `tcp` |
| Конкретный порт | `tcp.port == 445` |
| Переподключения TCP | `tcp.analysis.retransmission` |
| Потерянные пакеты | `tcp.analysis.lost_segment` |
| ICMP | `icmp` |
| Широковещательный трафик | `eth.dst == ff:ff:ff:ff:ff:ff` |
| Только HTTP | `http` |
| Скрыть фоновый шум | `not arp and not icmp and not dns` |

Полезные пункты меню: `Statistics → Conversations` (кто с кем и сколько),
`Statistics → Endpoints` (все узлы), `Statistics → Protocol Hierarchy` (состав
трафика), `Analyze → Follow → TCP Stream` (весь диалог целиком).

## Результаты и как их читать

Для отчёта заказчику обычно достаточно трёх вещей:

1. `Statistics → Conversations` — кто инициировал обмен и сколько передал.
2. `Statistics → Protocol Hierarchy` — чем занят канал в процентах.
3. Скриншот конкретного обмена с применённым фильтром.

Первое, на что смотреть при жалобах на сеть: `tcp.analysis.retransmission`.
Много повторных передач — признак потерь, а потери почти всегда означают
проблему кабеля, Wi-Fi или перегруженного порта.

## Риски и предупреждения

> **Живой перехват требует Npcap** — драйвера уровня ядра. Портативная сборка
> его не ставит. Установка Npcap на станцию заказчика — отдельное действие,
> требующее его согласия и прав администратора.

> Перехват трафика на чужой сети означает доступ к чужим данным, включая
> содержимое незашифрованных сессий. Делать только с разрешения владельца и
> только в объёме, нужном для диагностики.

> Дамп может содержать персональные данные и пароли из незашифрованных
> протоколов. Не хранить дампы на флешке после выезда, передавать заказчику
> вместе с отчётом.

> Большой дамп требует памяти: на разбор файла в несколько гигабайт нужно
> существенно больше оперативной памяти, чем весит файл.

> Портативной сборке нужен Visual C++ Redistributable x64. На чистой станции
> его может не быть.

**Что требует GPLv2+ при распространении.** Вместе с бинарной копией должны
**Обязанность прилагать текст лицензии не возникает.** GPL v2 требует, чтобы
текст лицензии и уведомление о правах ехали вместе с бинарной копией **при её
распространении**. С 2026-10-16 профиль некоммерческий: флешка личная, копия
никому не передаётся, значит распространения нет и обязательство не возникает
(`research/25-profile-change.md`, категория B).

Прежняя запись исходила из коммерческого выезда и требовала положить текст
GPL-2.0 рядом с бинарником; это действие снято решением владельца 2026-10-16.

Оговорка, которую нельзя потерять: обязательство вернётся, если флешка
когда-либо будет передана другому человеку или её содержимое выложено
публично. Тогда рядом с `WiresharkPortable64_4.6.9.paf.exe` нужен текст GPL-2.0 — из архива утилиты либо с
`gnu.org/licenses/`.

**Версия не сверена с первоисточником напрямую**: `wireshark.org` недоступен из
рабочей среды (`http=000`). Версия 4.6.9 и размеры сборок взяты из поисковой
выдачи от 2026-10-07: инсталлятор `Wireshark-4.6.9-x64.exe` — 93.4 МБ,
портативная `WiresharkPortable64_4.6.9.paf.exe` — 103.3 МБ, ARM64 — 78.4 МБ.

**Про SHA256.** В `microsoft/winget-pkgs` пакет `WiresharkFoundation.Wireshark`
версии **4.6.9** есть, то есть версия совпадает с нашей, но суммы в манифесте
относятся к **официальным установщикам**, а не к портативной сборке:

| Файл в манифесте WinGet | SHA256 |
|---|---|
| `Wireshark-4.6.9-x64.exe` (nullsoft) | `bf9b5ce8a89f244c376a9b1a946276eaa06463dde3e33069a34d7f102f5878cf` |
| `Wireshark-4.6.9-x64.msi` (wix) | `1975dfc96581a9b674fda3f41ac1585963b4ba52ea9459f3b6d9cedfac3a7217` |

У нас на флешке лежит `WiresharkPortable64_4.6.9.paf.exe` — пересборка
PortableApps.com, другой файл. Ни одна из двух сумм к нему не относится,
поэтому в манифест они не перенесены: та же ситуация, что у `CrystalDiskInfo`,
где сумма из каталогов описывает `.exe`-установщик, а не портативный ZIP.
`wireshark.org` и `portableapps.com` вне белого списка. Строка остаётся
`planned` с причиной (§4).
Прежняя стабильная ветка — 4.4.x.

Свежий драйвер `Npcap` — `npcap-1.89.exe` с `npcap.com`, подтверждено
официальной страницей загрузки Nmap, где он указан как последняя версия.
