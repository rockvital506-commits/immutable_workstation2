# remote/ — удалённый доступ

Самая насыщенная подкатегория по количеству средств — и единственная, где
выбор инструмента определяется не возможностями, а тем, **что разрешено
пропустить межсетевой экран заказчика**.

## Основное средство

[`RustDesk/`](RustDesk/) — версия 1.5.0, AGPL-3.0. Основной инструмент мастера.

Почему он, а не то, что уже есть в Strelec:

| Свойство | Значение для нас |
|----------|------------------|
| Открытый код | Единственное проверяемое средство удалённого доступа в наборе |
| Коммерческое использование | AGPL-3.0 без ограничений и без эвристики блокировки «коммерческого использования» |
| Свой сервер | Бесплатный `hbbs` + `hbbr`, данные не идут через чужую инфраструктуру |
| Портативный режим | `--noinstall` — запуск с флешки без установки |
| Работа в локальной сети | `src/lan.rs` — обнаружение узлов **без сервера согласования** |
| Автоматизация | `--connect`, `--file-transfer`, `--port-forward`, `--silent-install` |

## Запасные — в Strelec, не дублируются

| Утилита | Когда брать |
|---------|-------------|
| `TeamViewer 15` | У заказчика уже стоит, или его экран разрешает только его |
| `AnyDesk` | Плохой канал, нужен минимальный трафик |
| `Ammyy Admin 3.9 / 3.5.2.1` | Совместимость со старыми станциями. Учитывать, что антивирусы помечают его как инструмент злоумышленников |
| `AeroAdmin 4.9` | Нужен доступ без установки на стороне клиента |
| `Radmin 3.5.2.1` | Работа в домене, свой сервер |
| `Radmin VPN 2.0.4899.9` | Нужен туннель, а не управление |
| `UltraVNC` / `TightVNC` | Порт VNC уже открыт |
| `OpenVPN 2.5.8` | Нужен именно VPN |

Полный список — [`../../diagnostics/strelec-tools.md`](../../diagnostics/strelec-tools.md).

## Порядок выбора

1. Есть ли на станции уже установленное средство, которое заказчик знает?
   Если да — использовать его, не пугать человека новой программой.
2. Межсетевой экран заказчика пропускает ли что-то? Проверить одним
   подключением, а не перебором.
3. Локальная сеть есть, интернета нет? Тогда RustDesk в LAN-режиме, см.
   [`../wifi/`](../wifi/) про связку с точкой доступа.
4. Ничего не проходит? Выезд.

## Несанкционированный доступ

Несеансовый доступ (`RustDesk --silent-install` или `--install-service`) — это
постоянный канал в машину заказчика.

> Ставить только с явного согласия заказчика и фиксировать это в заявке: что
> установлено, каким ключом, кто имеет доступ, как снять.

> Постоянный пароль не должен совпадать у разных заказчиков.

> При завершении обслуживания средство несеансового доступа снимать или
> отключать, если договором не предусмотрено иное.

## Проверка после подключения

| Что | Как |
|-----|-----|
| Соединение установлено | Статус в клиенте |
| Куда смотрит клиент | Настройки сервера: адрес `hbbs`, ключ, реле `hbbr` |
| Права достаточно | Диспетчер задач запускается, службы видны |
| Файлы передаются | Пробная передача в обе стороны |

## Правила

> Не оставлять сессию открытой без присмотра. Любая открытая сессия — это
> доступ к данным заказчика.

> Не устанавливать несеансовый доступ «на всякий случай». Только когда он нужен
> по договору.

> Не хранить пароли доступа на флешке в открытом виде.

## Не проверено на месте

| Пункт | Что нужно |
|-------|-----------|
| Работа RustDesk 1.5.0 на IoT Enterprise LTSC 2024 | Прогон на станции |
| Проходимость публичного сервера через типовые межсетевые экраны | Наблюдение в выездах |
| Работа LAN-режима в связке с точкой доступа | Эксперимент на двух машинах |
