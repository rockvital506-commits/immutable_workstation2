# TCPView

## Назначение

Показывает все TCP- и UDP-конечные точки системы с привязкой к процессу: кто
держит соединение, куда оно идёт, в каком состоянии. Цветом подсвечивает
изменения — новые соединения и закрытые видны сразу.

Отвечает на вопрос «куда эта станция стучится прямо сейчас», который часто и
есть настоящий вопрос за жалобой «компьютер сам по себе что-то делает».

## Когда применять

- Станция обращается наружу без видимой причины.
- Нужно понять, какая программа занимает канал.
- Проверка, что после настройки межсетевого экрана соединение действительно
  не устанавливается.
- Поиск процесса, который держит порт и не даёт запустить службу.
- Подтверждение слов заказчика фактическими адресами.

## Запуск

```cmd
tcpview.exe
```

Имя исполняемого файла уточнить после распаковки: в архиве может
оказаться как общий `tcpview.exe`, так и отдельные сборки по разрядности.

Вывод в файл из командной строки:

```cmd
Tcpvcon.exe -accepteula -c > connections.csv
```

- Требуются права администратора: **да**, иначе не видны чужие процессы
- Работает из-под WinPE: **не проверено**
- Работает с флешки без установки: **да**
- Требует .NET / VC++ Redist: **нет**

## Ключи и типовые сценарии

| Задача | Что делать |
|--------|------------|
| Снимок в файл | `Tcpvcon.exe -accepteula -c > conn.csv` |
| Только установленные | В интерфейсе скрыть `TIME_WAIT` и `CLOSE_WAIT` |
| Найти процесс по порту | Колонка `Port`, потом `Process` |
| Куда именно идёт обмен | Колонка `Remote Address`; разрешать имена включено по умолчанию |
| Динамика | `Options → Update Speed` — чаще обновление, заметнее изменения |
| Скрыть шум | `Options → Show Unconnected Endpoints` снять |

Порядок в выезде: снять CSV **до** правок, сделать правку, снять после. Две
таблицы — это доказательство, что правка сработала.

## Результаты и как их читать

| Состояние | Что значит |
|-----------|-----------|
| `ESTABLISHED` | Соединение установлено |
| `LISTENING` | Процесс ждёт входящих |
| `TIME_WAIT` | Соединение закрыто, сокет ещё держится. Норма после активного обмена |
| `SYN_SENT` | Пытается соединиться и не может — межсетевой экран или узел недоступен |
| `CLOSE_WAIT` | Соединение закрыто с той стороны, а процесс не освободил сокет. Признак неаккуратной программы |

Много `SYN_SENT` на один адрес — станция куда-то настойчиво стучится и не
попадает. Это и есть то, что обычно ищут.

## Риски и предупреждения

> **Закрытие соединения — действие.** В интерфейсе можно разорвать соединение;
> делать это на чужой станции только с согласия заказчика.

> **Разрешение имён создаёт трафик.** Утилита пытается определить имена узлов,
> то есть сама обращается к DNS. На изолированной сети это не мешает, но в
> отчёте может появиться лишний шум.

> **Снимок содержит адреса и порты.** Это сведения о работе чужой сети. Не
> хранить после выезда и не передавать третьим лицам.

> Утилита показывает только то, что идёт через стек TCP/IP этой машины.
> Туннелированный трафик будет виден как одно соединение до узла туннеля.
