# firmware/ — группа «Прошивки»

Обновление и инвентаризация прошивок на станции владельца, без вскрытия
корпуса.

**Охват группы — только BIOS/UEFI материнской платы.** Решение владельца от
2026-10-14.

## Подкатегории

| Подкатегория | Что закрывает | Утилита здесь | Статус |
|--------------|---------------|---------------|--------|
| [`bios/`](bios/) | Инвентаризация версий, процедура обновления, бэкап SPI, чек-лист настроек UEFI | не нужны: утилита вендора из UEFI, `Intel FPT` для восстановления; свой скрипт `bios-inventory` | ✅ Этап 4.8 |

## Чего в группе нет намеренно

- **Файлов прошивок.** Прошивка привязана к конкретной модели и ревизии платы,
  универсального набора не существует, а устаревает он быстрее, чем
  используется. Так же, как с офлайн-обновлениями Windows в Этапе 7, вместо
  каталога — процедура: где взять, как проверить, как поставить.
- **Утилит прошивки NVMe и SATA.** Решение владельца: охват группы — только
  BIOS/UEFI. `nvme-cli` описан в исследовании, если понадобится — это
  отдельная подкатегория `storage/`.
- **`fwupd` и LVFS.** Для целевой станции MSI обновлений через LVFS нет:
  вендор не публикует там прошивки ноутбуков. Как инвентаризатор `fwupd`
  дублирует `HWiNFO` из Strelec, который уже есть на флешке.
- **Прошивки домашних роутеров.** Унификации нет: прошивка — это веб-интерфейс
  вендора и файл с его сайта, которого заранее не получить. Решение владельца
  от 2026-10-14 — исключить. В алгоритме диагностики сети остаётся только
  пункт «записать текущую версию прошивки роутера».
- **DOS-сборок с вендорскими утилитами.** Категория `ISO/firmware/` не
  создаётся: DOS-путь обновления устарел, для UEFI-плат не нужен.

## Главное ограничение

> **Наша флешка не подходит для файла прошивки ни одним разделом.**
> Утилита прошивки MSI требует **FAT32**. У нас раздел `Ventoy` — exFAT,
> `Tools` — NTFS, `VTOYEFI` — FAT16 на 32 МБ и помечен «не изменять».
>
> Решение владельца: **отдельная маленькая FAT32-флешка** в комплекте.
> Подготовка — [`bios/fat32-stick.md`](bios/fat32-stick.md).

## Правила

> **Сначала инвентаризация, потом решение.** Версии BIOS, ME, прошивок
> накопителей и настройки UEFI фиксируются **до** любых изменений. После
> прошивки сверить уже не с чем. Скрипт: `bios/scripts/bios-inventory`.

> **Прошивка — не по умолчанию, а по показанию.** Обновление BIOS возвращает
> настройки UEFI к значениям по умолчанию и откатывает часть работы
> предыдущих этапов. Повод должен быть конкретным: неисправность,
> несовместимость, известная уязвимость.

> **BitLocker приостанавливается один раз на всё время работ.** Обновление прошивки
> меняет измерения загрузки в TPM. При привязке к PCR 7/11 обновление
> прошивки вендора терпимо, при уходе на PCR 0,2,4,11 — станция уходит в
> восстановление BitLocker. Приостановить до первой операции с прошивками или
> образами, возобновить после проверки — не по нескольку раз.
> См. [`../security/encryption/README.md`](../security/encryption/README.md).

> **Откат готовится до прошивки.** Бэкап SPI, ключ восстановления BitLocker,
> снимок настроек UEFI — всё до, не после.

## Не проверено на месте

| Пункт | Что нужно |
|-------|-----------|
| Версии BIOS и ME на целевой станции MSI B12M-211RU | Прогон `bios-inventory` на станции |
| Модель NVMe в целевой станции | Там же |
| Поведение M-FLASH / UEFI BIOS Update с GPT-носителем из нескольких разделов | Только отдельные сообщения сообщества; проверять на станции нельзя |
| Условия лицензии Intel FPT для сервисного применения | Сайт Intel недоступен из рабочей среды |
| Условия хранения файлов прошивок MSI на коммерческом носителе | `msi.com` недоступен |
| Наличие `fptw64.exe` и `MEInfoWin` в Strelec 2026.02.05 | Проверить при работе |

Обоснование состава группы — [`../../research/14-firmware-update.md`](../../research/14-firmware-update.md).
