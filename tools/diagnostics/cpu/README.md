# cpu/ — стресс-тесты процессора и подсистем

## Состав

| Утилита | Версия | Среда | Что нагружает | Лицензия |
|---------|--------|-------|---------------|----------|
| [`Prime95/`](Prime95/) | 31.06 Build 1 | Windows, портативно | CPU и память, предельный нагрев | Freeware |
| [`stress-ng/`](stress-ng/) | 0.22.01 | Linux (Live Mint) | Выбранная подсистема: CPU, кэш, память, ввод-вывод | GPL v2 |

## Выбор инструмента

| Ситуация | Чем |
|----------|-----|
| Станция в своей Windows, нужен максимальный нагрев | Prime95, Small FFTs |
| Проверить контроллер памяти | Prime95, Blend |
| Станция в Live Mint | `stress-ng` |
| Нагрузить только память или только ввод-вывод | `stress-ng --vm` / `--hdd` |
| Нужен измеримый и воспроизводимый результат | `stress-ng --metrics` |

## Длительность

| Цель | Время |
|------|-------|
| Быстрая оценка | 30 минут |
| Надёжный вывод о стабильности | 2–4 часа |
| Проверка после замены термоинтерфейса | до выхода на плато температуры, обычно 30–60 минут |

## Критерий «станция стабильна»

- Ошибок вычислений нет (`FATAL ERROR` в Prime95, `failed` в stress-ng).
- Температура не выше допустимой для CPU (для i3-1215U — до 100 °C по
  спецификации, но устойчивая работа выше 95 °C уже повод смотреть охлаждение).
- Частоты не падают ниже базовой после прогрева — иначе троттлинг.

## Риски

> Стресс-тест нагревает систему до предела. На ноутбуке с забитым радиатором
> или высохшей термопастой возможна аварийная остановка.

> При аварийной перезагрузке теряются несохранённые данные. Закрыть всё и
> предупредить заказчика.

> Не оставлять без присмотра.

> На станции с деградировавшим питанием тест может вывести её из строя — это
> осознанный диагностический риск, согласовывать с заказчиком.
