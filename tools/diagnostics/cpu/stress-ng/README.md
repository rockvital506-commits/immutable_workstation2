# stress-ng

## Назначение

Управляемая нагрузка на конкретные подсистемы: CPU, кэш, оперативная память,
ввод-вывод, файловая система. В отличие от Prime95, который бьёт по всему
сразу, `stress-ng` позволяет нагружать выбранное и измерять результат.

Работает в Linux. На флешке используется из Live-среды Linux Mint.

## Когда применять

- Станция уже в Live Mint, перезагружаться в Windows не хочется.
- Нужно нагрузить только память или только ввод-вывод, а не CPU целиком.
- Нужен воспроизводимый тест с измеряемым результатом — `bogo ops` в логе.
- Проверка охлаждения под длительной, но дозированной нагрузкой.

## Запуск

```bash
# Установка в Live Mint (нужен persistence, иначе уйдёт после перезагрузки)
sudo apt update && sudo apt install -y stress-ng

# Из исходников
tar xf stress-ng-0.22.01.tar.gz && cd stress-ng-0.22.01
make -j"$(nproc)" && sudo make install
```

- Требуются права администратора: **да** для части тестов
- Работает из-под WinPE: **нет**, это Linux
- Работает с флешки без установки: **да**, собранный бинарник можно носить с собой
- Требует .NET / VC++ Redist: **нет**

## Ключи и типовые сценарии

| Задача | Команда |
|--------|---------|
| Нагрузить все ядра на 60 секунд | `stress-ng --cpu 0 --timeout 60s` |
| Проверка памяти | `stress-ng --vm 4 --vm-bytes 1G --timeout 120s` |
| Нагрузка на кэш | `stress-ng --cache 4 --timeout 60s` |
| Ввод-вывод | `stress-ng --io 4 --hdd 2 --timeout 120s` |
| Всё сразу с измерением | `stress-ng --cpu 0 --vm 2 --io 2 --metrics --timeout 300s` |
| Результат в файл | `stress-ng --cpu 0 --timeout 60s --metrics-brief 2>&1 \| tee reports/stress.log` |
| Проверка на ошибки вычислений | `stress-ng --cpu-method matrixprod --verify --timeout 60s` |
| Список доступных методов | `stress-ng --cpu-method which` |

Ключ `--verify` важен: без него утилита просто нагружает, а не проверяет
правильность вычислений.

## Результаты и как их читать

| Показатель | Смысл |
|-----------|-------|
| `bogo ops` | Условные операции — мера производительности под нагрузкой |
| `bogo ops/s` | То же в секунду; сравнивать между прогонами на одной машине |
| строки `failed` / `untrusted` | Обнаружены ошибки вычислений — железо нестабильно |
| падение `bogo ops/s` между прогонами | Троттлинг по нагреву |

Абсолютные значения `bogo ops` между разными машинами сравнивать смысла нет.
Сравнивают прогон с прогоном на одной станции и наличие ошибок.

## Риски и предупреждения

> Как и любой стресс-тест, нагревает систему до предела. На ноутбуке с забитым
> радиатором возможна аварийная остановка. Не оставлять без присмотра.

> `--hdd` пишет на диск во временные файлы. Убедиться, что места достаточно и
> что работа идёт не на разделе с данными заказчика.

> `--vm` с большим `--vm-bytes` может увести станцию в swap или в OOM. На 8 ГБ
> ОЗУ не задавать суммарный объём больше доступной памяти.
