# Регламент обновления флешки

**Две разные процедуры, и смешивать их нельзя.** Обновление самого Ventoy
меняет загрузчик. Обновление содержимого меняет образы, утилиты и скрипты.
Первое делается редко и требует осторожности, второе — регулярно и рисков не
несёт.

> **База пути.** Непомеченные пути в этом документе считаются от корня
> репозитория. Префиксы `CONVENTIONS.md` §10.1 применяются там, где путь
> указывает на раздел флешки.

Периодичность по решению заказчика: **полная сверка раз в месяц**, обновление
содержимого — по факту выхода новой версии утилиты или образа.

## А. Обновление Ventoy

### Когда нужно

- Нужна поддержка нового образа, которого текущая версия не знает.
- Исправление, относящееся к нашей загрузке.
- Плановый переход на актуальную версию.

Актуальная на 2026-10-15 — **1.1.18**. Минимум для этой флешки — **1.1.14**
(`VTOY_SECURE_BOOT_POLICY` в конфиге), для файлов ответа станции — **1.1.11**.

### Что можно обновлять на месте, а что нет

| Действие | Update | Install (переустановка) |
|----------|--------|-------------------------|
| Новая версия Ventoy | **да** | не нужно |
| Новый образ в `ISO/` | обычное копирование файла | не нужно |
| Новый файл в `ventoy/`, `builds/` | обычное копирование | не нужно |
| Изменение `ventoy.json` | правка файла | не нужно |
| Смена MBR ↔ GPT | **нет** | **требуется**, данные раздела 0 стираются |
| Изменение размера раздела | **нет** | **требуется** |
| Восстановление повреждённого загрузчика | обычно достаточно | если не помогло |

**Ключевая строка таблицы — смена MBR ↔ GPT.** Наша флешка GPT. Если
понадобится MBR, это переустановка со стиранием раздела 0, а не обновление.

### Порядок

1. **Бэкап до любых действий** — [`flash-backup.md`](flash-backup.md). Это не
   формальность: `Update` сохраняет файлы по замыслу разработчика, но
   спроектированное поведение — не замена резервной копии.
2. Проверить текущую версию: `Ventoy2Disk.exe` показывает её при запуске, либо
   `F2` в меню Ventoy.
3. Скачать новую версию с официального сайта, распаковать.
4. Запустить `Ventoy2Disk.exe` от имени администратора, выбрать носитель,
   нажать **Update**. Не Install.
5. Дождаться завершения и безопасного извлечения.
6. **Первая загрузка:** при включённом Secure Boot Ventoy с версии 1.1.14
   использует shim, подписанный UEFI CA 2023, и новый ключ нужно записать в
   прошивку. Ventoy предложит это сделать сам. Без записи флешка не
   загружается, и это легко принять за неисправность носителя.
7. Проверка после обновления — раздел «Проверка после любого обновления» ниже.

### Чего не делать

- **Не править конфиг через VentoyPlugson на версиях до 1.1.16.** В релизе
  1.1.16 исправлен сброс значения `VTOY_WIN_UEFI_RES_LOCK` при входе в
  Plugson, а у нас в конфиге стоит 3. На более ранней версии правка через
  веб-интерфейс могла молча его обнулить.
- **Не нажимать Install вместо Update.** Install стирает раздел 0.
- **Не обновлять без бэкапа**, даже если «обновление же сохраняет файлы».

## Б. Обновление содержимого

### Образы

1. Скачать образ с официального источника.
2. Проверить SHA256 сверкой с опубликованной суммой.
3. Положить в `ISO/<группа>/` под исходным именем — по имени сверяется сумма.
4. Создать или обновить заглушку в репозитории: `scripts/new-iso-stub.sh`.
5. Внести строку в `manifest.csv` с суммой, размером, версией.
6. Старый образ удалять **после** проверки нового, а не до.

### Утилиты

1. Скачать новую версию.
2. Проверить SHA256.
3. Заменить файл в `tools/<группа>/<подкатегория>/<утилита>/`.
4. Обновить заглушку `<имя>.<расширение>.md`: версия, сумма, размер, дата.
5. Обновить строку `manifest.csv`.
6. Если у утилиты изменился интерфейс — проверить процедуры в
   [`../scripts/procedures/`](../scripts/procedures/), которые на неё
   ссылаются.

### Скрипты и конфиги

Скрипты и конфиги хранятся в git. Обновление — это правка в репозитории и
копирование на флешку, а не наоборот. Изменение на флешке, не внесённое в
репозиторий, теряется при следующем копировании.

Правило дуальности: правка в `.sh` означает такую же правку в `.ps1`, и
наоборот.

### Порядок применения инструментов на станции

Если обновлялся инструмент из цепочки настройки Windows, порядок применения
может иметь значение: Win11Debloat → WinUtil → Sophia Script → свои скрипты.
WinUtil удаляет ключ, который ставится после него. Подробнее —
[`../scripts/procedures/basic-setup.md`](../scripts/procedures/basic-setup.md).

## Проверка после любого обновления

Обязательно, в этом порядке:

```bash
# 1. Структура и соглашения
bash scripts/repo-validate.sh

# 2. Манифест
python3 scripts/csv-check.py manifest.csv

# 3. Флешка против репозитория, со сверкой сумм
bash scripts/check-flash.sh --ventoy <раздел0> --tools <раздел2> --verify
```

Третья команда выводит итог сверки: сколько сумм сверено, сколько строк без
суммы, сколько файлов отсутствует. **Код возврата 0 при нуле сверенных сумм —
не признак благополучия**: это значит, что сверять было нечего.

Дополнительно:

- загрузка с флешки в UEFI — меню Ventoy появляется, образы видны;
- `ventoy.json` на флешке совпадает с репозиторием (проверяет `check-flash`);
- один образ реально загружается — не «виден в меню», а загружается.

## Если обновление пошло не так

| Симптом | Что делать |
|---------|-----------|
| Флешка не загружается после Update | Записать ключ UEFI CA 2023, либо отключить Secure Boot |
| Образ не виден в меню | Проверить имя и расширение, посмотреть вывод Ventoy при сканировании |
| Образ виден, но не грузится | Попробовать режим WIMBOOT из дополнительного меню Ventoy |
| Сумма не совпадает | Не использовать файл, скачать заново |
| Раздел 0 повреждён | Восстановление из бэкапа — [`flash-backup.md`](flash-backup.md) |
