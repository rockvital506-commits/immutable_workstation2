# Регламент переустановки

Два разных случая, и путать их нельзя:

| Случай | Что делать |
|--------|-----------|
| Целевая станция MSI Modern 15 B12M-211RU | Алгоритм станции, шаги 1–12: `builds/MSI_B12M-211RU_Win11_LTSC_IoT_24H2/algorithm.md` |
| Произвольная станция | Этот регламент |

Алгоритм станции содержит специфичное для неё: файл ответа, драйверы, порядок
настройки. Здесь — только общее.

## 0. До начала

1. Выбрать образ по [compatibility.md](compatibility.md). Проверить срок
   поддержки: ставить редакцию, которая снимается с поддержки в ближайшие
   месяцы, — значит создать владельцу проблему.
2. Проверить, что файл образа на флешке и его SHA256 совпадает с манифестом.
3. Проверить версию Ventoy на флешке — см. шаг 1 ниже.
4. Убедиться, что есть куда скопировать данные станции.

## 1. Версия Ventoy

Минимум **1.1.14**, рекомендуется **1.1.18** (релиз 2026-10-09).

Почему именно 1.1.14:

- `VTOY_SECURE_BOOT_POLICY` в нашем `ventoy.json` появился в 1.1.14;
- переменная `$$VT_WINDOWS_DISK_NONVTOY_CLOSEST_XXX$$` в файлах ответа —
  в 1.1.11;
- 1.1.16 исправил сброс `VTOY_WIN_UEFI_RES_LOCK` при входе в VentoyPlugson,
  а у нас в конфиге стоит значение 3.

Проверить версию: `Ventoy2Disk.exe` показывает её при запуске, либо в меню
Ventoy нажать `F2`.

## 2. Создание или обновление носителя

Разметка целевой флешки: GPT, три раздела.

| № | Метка | ФС | Размер | Содержимое |
|---|-------|----|--------|-----------|
| 0 | `Ventoy(...)` | exFAT | 340.72 ГБ | `ISO/`, `ventoy/`, `builds/`, `backup/` |
| 1 | `VTOYEFI` | FAT16 | 32 МБ | Загрузчики Ventoy. **Не изменять** |
| 2 | `Tools_SD400(...)` | NTFS | 128.00 ГБ | Утилиты, скрипты, документация |

**Обновление Ventoy на существующем носителе** (`Ventoy2Disk.exe` → Update)
сохраняет данные на разделе Ventoy. **Установка заново** (Install) — стирает
раздел Ventoy целиком. Перед Install скопировать `ISO/`, `ventoy/`, `builds/`,
`backup/`.

### Запись ключа Secure Boot — обязательно знать

С версии 1.1.14 Ventoy использует shim, подписанный новым сертификатом
**UEFI CA 2023** (старые сертификаты Secure Boot истекают в 2026 году). При
**первой загрузке** после установки или обновления Ventoy новый ключ нужно
записать в прошивку — Ventoy предложит это сделать сам.

Если этого не знать, выглядит так: флешка не загружается на станции с
включённым Secure Boot, и это легко принять за неисправность носителя.

Два варианта действий:

- записать ключ через меню Ventoy при первой загрузке;
- временно отключить Secure Boot в прошивке.

Для Strelec Secure Boot всё равно желательно отключать — автор сборки не
гарантирует загрузку с ним.

## 3. Размещение образа

Образ кладётся в `ISO/<группа>/`:

| Каталог | Что там |
|---------|---------|
| `ISO/windows/` | Установочные образы Windows |
| `ISO/winpe/` | Strelec |
| `ISO/linux/` | Linux Mint |
| `ISO/backup/` | Clonezilla |

Имя файла — как в источнике, без правок: по имени сверяется SHA256.

## 4. Файл ответа — только для целевой станции

Правило проекта: **файл ответа принадлежит сборке**, а не общему каталогу.
Файлы лежат в `builds/MSI_B12M-211RU_Win11_LTSC_IoT_24H2/answer/`.

Перед установкой:

1. Скопировать нужный файл в каталог, указанный в `ventoy.json`, **под именем
   `autounattend.xml`**.
2. Внести правки в `ventoy/ventoy.json` — точные строки приведены в шаге 6
   алгоритма станции.

Три запрета, каждый из которых ломает установку молча:

| Нельзя | Почему |
|--------|--------|
| Класть `autounattend.xml` в корень флешки | Будет применяться ко всем образам, и отказаться от него нельзя |
| Хранить файлы ответа в `ventoy/autoinstall/` | Каталог общий, файлы в нём принадлежат неизвестно какой сборке |
| Задавать `timeout` и `autosel` в блоке `auto_install` | С `autosel` шаблон применяется без меню — не останется шанса выбрать другой образ |

Для произвольной станции файла ответа нет: установка вручную. Файл с обходом
требований (`...-bypass.xml`) рассчитан на произвольное железо, но разметку
диска и имя компьютера надо править под конкретную станцию.

## 5. Установка

1. Загрузка с флешки, выбор образа в меню Ventoy.
2. Если применялся файл ответа — установка пойдёт без вопросов. Точка
   невозврата — начало разметки диска: `WillWipeDisk` в файле ответа равен
   `true`, всё содержимое целевого диска стирается.
3. Если установка пошла в ручном режиме, хотя ожидалась автоматическая —
   значит файл ответа не подхватился. Прерывать не обязательно, но причину
   смотреть в `C:\Windows\Panther\` после установки.

## 6. После первой загрузки

Порядок задан и менять его нельзя — каждая процедура предполагает состояние,
которое оставила предыдущая:

1. [`../scripts/procedures/basic-setup.md`](../scripts/procedures/basic-setup.md)
   — обновления, драйверы, базовая настройка.
2. [`../scripts/procedures/block-telemetry.md`](../scripts/procedures/block-telemetry.md)
   — блокировка телеметрии, GPO, задача планировщика.
3. [`../scripts/procedures/ssd-ram-tuning.md`](../scripts/procedures/ssd-ram-tuning.md)
   — накопитель и память.
4. Ключ продукта и активация — шаг 12 алгоритма станции. До него система не
   активирована, и это ожидаемое состояние: файл ответа задаёт GVLK, который
   лицензией не является.
4. [`../scripts/procedures/validation.md`](../scripts/procedures/validation.md)
   — приёмка. Три прогона, коды возврата различаются.

Проверка Центра обновления после блокировки обязательна: блокировка не должна
ломать обновления, и это проверяется, а не предполагается.

## 7. Завершение

## Если что-то пошло не так

| Симптом | Куда смотреть |
|---------|---------------|
| Установка в ручном режиме вместо автоматической | `C:\Windows\Panther\unattend.xml` и журналы рядом |
| ОС встала не на тот диск | Переменная диска в файле ответа; версия Ventoy не ниже 1.1.11 |
| Флешка не грузится при Secure Boot | Запись ключа UEFI CA 2023, шаг 2 |
| Strelec не грузится | Secure Boot — отключить |
| Не работает сеть после установки | Драйверы: [`../drivers/`](../drivers/) |
| Центр обновления не работает после блокировки | `validation.md`, проверка 2 |
