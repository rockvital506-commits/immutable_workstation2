# Чек-лист выезда

Один лист. Печатать двусторонне: до выезда — первая половина, по возвращении —
вторая.

---

## До выезда

### Носитель

- [ ] Флешка в сумке, колпачок на месте
- [ ] Вторая маленькая флешка FAT32 — для обновления BIOS, см.
      [`../firmware/bios/`](../firmware/bios/)
- [ ] Версия Ventoy не ниже **1.1.14**
- [ ] `SHA256` нужного образа сверен с `manifest.csv`
- [ ] Свободное место на разделе Tools есть

### Задание

- [ ] Что за станция: модель, что жалуются
- [ ] Какой образ нужен — сверено с [compatibility.md](compatibility.md)
- [ ] Срок поддержки этого образа не истекает в ближайшие месяцы
- [ ] Для целевой станции: файл ответа выбран, правки `ventoy.json` известны
- [ ] Куда копировать данные, если потребуется

### Оборудование

- [ ] Переходник USB, удлинитель
- [ ] Блок питания совместимого типа — на случай, если станция не включается
- [ ] Внешний накопитель для копии данных
- [ ] Телефон для фотографий подключений и экранов ошибок
- [ ] Бумага и ручка — на станции может не оказаться ничего пишущего

## На станции

### До любых действий

- [ ] Спросил про данные: что важно, есть ли копия
- [ ] Сфотографировал подключения
- [ ] Записал, что именно не работает, словами заказчика

### Инвентаризация

Записать, не полагаясь на память:

| Что | Значение |
|-----|----------|
| Модель, серийный номер | |
| Процессор | |
| Память, всего и свободно слотов | |
| Накопитель: модель, объём, тип | |
| Версия BIOS/UEFI и дата | |
| Предустановленная система | |
| Ключ продукта: где — наклейка, прошивка, учётка | |
| Тип ключа: OEM / Retail / MAK / цифровая лицензия | |
| Если Retail — на какой станции использовался раньше | |
| Шифрование диска включено? | |
| Secure Boot включён? | |
| Порядок загрузки | |

### Выбор образа — решение заказчика, не мастера

Критерии назвать вслух и записать ответ:

| Критерий | Ответ заказчика |
|----------|-----------------|
| Привычный инструмент, чем работает каждый день | |
| Приложение, которое нужно и не работает на новой ОС | |
| Срок эксплуатации станции | |
| Доступ в интернет: изолированная или в сети | |
| Важно ли, чтобы система не менялась годами | |
| Что есть по лицензии | |

- [ ] Факты о сроке поддержки названы заказчику вслух
- [ ] Если поддержка истекла или истекает — заказчик об этом предупреждён
- [ ] Решение принято заказчиком, не мастером

**Выбранный образ и причина выбора** — записать обязательно, иначе на
следующем выезде причина неизвестна и решение принимается заново:

```
Образ:
Причина:
Кто решил:
Дата:
```

### Работы

- [ ] Данные скопированы, **копия открыта и читается**
- [ ] Выполнено по регламенту: `recovery.md` или `reinstall.md`
- [ ] Точка невозврата пройдена осознанно: заказчик предупреждён, что
      содержимое диска стирается
- [ ] При установке Windows: файл ответа подхвачен, установка не в ручном
      режиме
- [ ] После первой загрузки: процедуры в порядке
      `basic-setup` → `block-telemetry` → `ssd-ram-tuning` → `validation`
- [ ] Центр обновления проверен после блокировки — работает
- [ ] Ключ продукта введён, `slmgr /dlv` показывает `Licensed`
- [ ] Тип лицензии в `/dlv` совпадает с тем, что дал заказчик
- [ ] Если ключ Retail с другой станции — отвязка выполнена (`slmgr /upk`,
      `slmgr /cpky` на старой станции)
- [ ] Драйверы выгружены в каталог сборки
- [ ] Образ системы снят

## По возвращении

- [ ] Чек-лист перенесён в постоянный журнал
- [ ] Изменения на флешке внесены в
      [CHANGELOG-flash.md](CHANGELOG-flash.md)
- [ ] Новые драйверы и образы добавлены в `manifest.csv` с SHA256
- [ ] Если станция новая и требует отдельной сборки — создан каталог в
      `builds/` по правилам `CONVENTIONS.md`
- [ ] Что не проверено на месте — записано в «Не проверено» соответствующего
      документа

## Три правила, которые нарушаются чаще всего

1. **Копия данных без проверки — не копия.** Открыть файл с нового места.
2. **Не писать на диск, с которого восстанавливаешь.**
3. **Не начинать переустановку, не спросив про данные.** Заказчик часто
   считает, что «там ничего важного», и вспоминает об обратном после.
