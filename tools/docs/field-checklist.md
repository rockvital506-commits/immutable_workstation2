# Чек-лист работ со станцией

Один лист. Печатать двусторонне: подготовка — первая половина, завершение —
вторая.

**Профиль с 2026-10-16 — домашняя лаборатория, некоммерческое использование**
(`CONVENTIONS.md` §7.1 шаг 3). Чек-лист раньше назывался «Чек-лист выезда» и
был построен вокруг выезда к заказчику. Выезда больше нет: станции свои, сети
свои, исполнитель и владелец — одно лицо.

Что при этом **сохранено намеренно**, а не по инерции:

- **Инвентаризация письменно.** Своё железо не повод полагаться на память:
  через полгода модель планки или версия BIOS вспоминаются только по записи.
- **Выбор образа — факты, затем решение, затем запись.** Совпадение владельца
  и исполнителя в одном лице не отменяет того, что решение должно быть
  осознанным и записанным.
- **Ограничение «без вскрытия».** Сохранено решением владельца от 2026-10-16 как
  принцип минимального вмешательства, хотя разборка физически доступна.
- **Пост-тесты.** Проверка Центра обновления после блокировки и проверка
  читаемости копии — не бюрократия, а единственная защита от самоуверенности.

Что **убрано** как потерявшее основание: заявки, согласие владельца на
обработку данных, передача станции, отчёт по возвращении заказчику.

## До начала

### Носитель

- [ ] Флешка подключена, колпачок на месте
- [ ] Вторая маленькая флешка FAT32 — для обновления BIOS, см.
      [`../firmware/bios/`](../firmware/bios/)
- [ ] Версия Ventoy не ниже **1.1.14**, рекомендуемая **1.1.18**
- [ ] `SHA256` нужного образа сверен с `manifest.csv`
- [ ] Свободное место на разделе Tools есть

### Задача

- [ ] Что за станция: модель, что именно не устраивает или не работает
- [ ] Какой образ нужен — сверено с [compatibility.md](compatibility.md)
- [ ] Срок поддержки этого образа не истекает в ближайшие месяцы
- [ ] Для целевой станции: файл ответа выбран, правки `ventoy.json` известны
- [ ] Куда копировать данные, если потребуется

### Оборудование

- [ ] Переходник USB, удлинитель
- [ ] Блок питания совместимого типа — на случай, если станция не включается
- [ ] Внешний накопитель для копии данных
- [ ] Телефон для фотографий подключений и экранов ошибок
- [ ] Бумага и ручка — рядом может не оказаться ничего пишущего

## На станции

### До любых действий

- [ ] Записано, что важно на диске и есть ли копия
- [ ] Сфотографированы подключения
- [ ] Записано, что именно не работает, своими словами — не «глючит», а что
      конкретно и после чего

### Инвентаризация

Записать, не полагаясь на память:

| Что | Значение |
|-----|----------|
| Модель, серийный номер | |
| Процессор | |
| Память, всего и свободно слотов | |
| Накопитель: модель, объём, тип | |
| Версия BIOS/UEFI и дата | |
| Предустановленная система | |
| Ключ продукта: где — наклейка, прошивка, учётка | |
| Тип ключа: OEM / Retail / MAK / цифровая лицензия | |
| Если Retail — на какой станции использовался раньше | |
| Шифрование диска включено? | |
| Secure Boot включён? | |
| Порядок загрузки | |

### Выбор образа — факты, затем решение, затем запись

Критерии назвать вслух и записать ответ:

| Критерий | Ответ |
|----------|-------|
| Привычный инструмент, чем работает каждый день | |
| Приложение, которое нужно и не работает на новой ОС | |
| Срок эксплуатации станции | |
| Доступ в интернет: изолированная или в сети | |
| Важно ли, чтобы система не менялась годами | |
| Что есть по лицензии | |

- [ ] Факты о сроке поддержки названы вслух
- [ ] Если поддержка истекла или истекает — это записано явно
- [ ] Решение записано вместе с причиной, а не только результат

**Выбранный образ и причина выбора** — записать обязательно, иначе через
полгода причина неизвестна и решение принимается заново:

```
Образ:
Причина:
Дата:
```

Строка «Кто решил» убрана: при домашнем профиле владелец и исполнитель — одно
лицо, и строка не несла бы информации.

### Работы

- [ ] Данные скопированы, **копия открыта и читается**
- [ ] Выполнено по регламенту: `recovery.md` или `reinstall.md`
- [ ] Точка невозврата пройдена осознанно: записано, что содержимое диска
      стирается
- [ ] При установке Windows: файл ответа подхвачен, установка не в ручном
      режиме
- [ ] После первой загрузки: процедуры в порядке
      `basic-setup` → `block-telemetry` → `ssd-ram-tuning` → `validation`
- [ ] Центр обновления проверен после блокировки — работает
- [ ] Ключ продукта введён, `slmgr /dlv` показывает `Licensed`
- [ ] Тип лицензии в `/dlv` совпадает с ожидаемым
- [ ] Если ключ Retail с другой станции — отвязка выполнена (`slmgr /upk`,
      `slmgr /cpky` на старой станции)
- [ ] Драйверы выгружены в каталог сборки
- [ ] Образ системы снят

## По завершении

- [ ] Чек-лист перенесён в постоянный журнал
- [ ] Изменения на флешке внесены в
      [CHANGELOG-flash.md](CHANGELOG-flash.md)
- [ ] Новые драйверы и образы добавлены в `manifest.csv` с SHA256
- [ ] Если станция новая и требует отдельной сборки — создан каталог в
      `builds/` по правилам `CONVENTIONS.md`
- [ ] Что не проверено на месте — записано в «Не проверено» соответствующего
      документа

## Три правила, которые нарушаются чаще всего

1. **Копия данных без проверки — не копия.** Открыть файл с нового места.
2. **Не писать на диск, с которого восстанавливаешь.**
3. **Не начинать переустановку, не записав, что на диске важно.** Формулировка
   «там ничего важного» регулярно оказывается неверной, и вспоминается об этом
   после.
