# Поэтапный план наполнения флешки

Логический порядок: **от чистой размеченной флешки до полностью заполненной**.
Каждый этап завершается коммитом и уведомлением о готовности.

---

## Этап 0 — Подготовка носителя (вне репозитория, выполняется на железе)

1. Выбрать носитель (USB-флешка / SSD в боксе), уточнить объём.
2. Проверить SMART и отсутствие бэд-блоков — флешка не должна подвести в полях.
3. Установить Ventoy (v1.1.17+) в режиме **GPT**, раздел 1 — exFAT или NTFS.
4. Создать раздел 2 (`TOOLS`) в оставшемся месте, форматировать в exFAT.
5. Сохранить дамп первых секторов диска в `ventoy-partition/backup/` — до любых правок.

**Результат:** физический носитель, схема разделов соответствует таблице в `README.md`.

`newline` — прежний вывод об этом был неверным.

## Этап 4.5 — security ✅

Исследование по правилу проекта №1 выполнено, результат —
`research/10-security-scanners-audit-encryption.md`. По правилу №2
реализация **не начата**: лицензионный вопрос при коммерческом профиле
требует решения заказчика.

Ключевой вывод: бесплатные портативные сканеры разрешают только личное
некоммерческое использование. Dr.Web CureIt! прямо требует коммерческую
лицензию для «услуг по лечению компьютеров другим лицам» (351–702,77 ₽ за ПК
в год), Emsisoft Emergency Kit — EEK Pro или Remediation Kit. Лицензии KVRT,
SmartFix и Microsoft Safety Scanner не проверены: сайты вендоров недоступны, а
каталоги противоречат друг другу. MSERT дополнительно истекает через 10 дней,
то есть на флешке храниться не может.

Strelec закрывает сканеры **по составу, но не по содержимому**: в
`SSTR/MInst/Portable/Antivirus` лежат пустышки. Аудита и шифрования в Strelec
нет вообще, Sysinternals тоже нет.

Единственная позиция без лицензионного риска — VeraCrypt 1.26.29, подтверждён
первоисточником через API GitHub (релиз 2026-06-12,
`VeraCrypt_Setup_x64_1.26.29.msi` 52 789 248 байт, лицензия TrueCrypt 3.0 +
Apache 2.0, коммерческое использование разрешено).

Исследование — `research/13-offline-updates.md`. По правилу №2 реализация не
начата, нужны решения.

Что показал AUDIT:

- **Постоянно хранящийся каталог обновлений — плохая идея.** Офлайн-MSU
  свежего накопительного занимает несколько гигабайт, каждое накопительное
  вытесняет предыдущее, а выходят они ежемесячно. Каталог устаревает быстрее,
  чем используется, и отнимает место у пака драйверов на ~50 ГБ.
- **SSU отдельно больше не существует**: для Windows 10 2004 и новее отдельные
  пакеты SSU не выпускаются с марта 2021 года, servicing stack встроен в LCU.
  Целевая станция (24H2, build 26100) — этот случай. Но при раздельной
  установке через DISM порядок SSU → LCU обязателен, а MSU делает это сам.
- **Откат не всегда возможен**: SSU не удаляется ключом `/uninstall`,
  изменения WinRE от SafeOS Dynamic Update необратимы. Единственный надёжный
  возврат — эталонный образ, который в алгоритме станции и так снимается.
- **Рекомендованный Microsoft способ**: положить все пакеты одного KB в один
  каталог и указать DISM на каталог — зависимости разрешатся автоматически.
- **Лицензия не проверена**: явного разрешения хранить скачанные пакеты на
  коммерческом носителе в первоисточнике найти не удалось, сайт недоступен.
  Это отличается от Этапа 4.5 — там запрет был сформулирован автором прямо,
  здесь нет ни запрета, ни разрешения.

пакет под целевую станцию в её сборке `ventoy-partition/builds/`; скрипт

загрузка из Microsoft Update Catalog, правило именования, манифест SHA256,
установка через `DISM /Add-Package` на каталог (рекомендованный Microsoft
способ), обязательный порядок SSU → LCU при раздельной установке и
предупреждение о том, что пакет с SSU не откатывается.

Отклонение от рекомендации AUDIT: вариант «один пакет под целевую станцию в её
сборке `ventoy-partition/builds/`» **не принят** — заказчик выбрал чистую
процедуру без хранимых пакетов. Пакет скачивается в выезд, если он понадобится.

**Скрипт интеграции** — пара `integrate-drivers.ps1` + `.sh` в
`tools/drivers/export/scripts/`. Оборачивает `DISM /Add-Driver /Recurse`
(в PowerShell — `Add-WindowsDriver`), считает INF до начала работы, различает
коды возврата `0`/`1`/`2`/`3`, поддерживает `--dry-run` и `-WhatIf`.
Обновлений Windows в нём нет намеренно: драйвер снимается через
`pnputil /delete-driver`, обновление с SSU не удаляется вовсе, и порядок отката
у них разный. Сущность зарегистрирована в `manifest.csv` и в `SELF_ENTITIES`.

Проверки: `tests/test_stage7.py` (54 проверки), включая живой прогон `.sh` —
`--help`, четыре кода возврата, отсутствие мусора после провала, наличие лога.
`.ps1` не выполнен ни разу: PowerShell в рабочей среде отсутствует.
