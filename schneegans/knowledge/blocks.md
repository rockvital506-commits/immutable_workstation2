# Устройство генератора

Основание: [S01, S02, S04, S06](../sources.md). Сведения о механизмах исследованы;
применение к конкретному билду ещё не согласовано и требует проверки практикой.

## Смысл

Веб-форма создаёт answer-файл для чистой установки Windows с USB или в VM.
Не заменяет инвентаризацию, бэкап, лицензию Windows или управление конфигурацией.
Не требует перепаковки ISO для обычного сценария автора; Ventoy — отдельная
интеграция. Поддержка 24H2/25H2/26H2 заявлена автором, не проверена нами на всех ОС.

## Не только XML-настройки

Результат может содержать стандартные компоненты Setup, встроенные файлы,
CMD/PowerShell/REG/VBS, задания планировщика. Галочка может менять реестр и
оставлять постоянную задачу. Проверять фактический XML и сценарии.

| Контекст | Назначение |
|---|---|
| System | До создания пользователей, системные изменения |
| DefaultUser | Шаблон будущих пользовательских профилей, не текущий HKCU |
| FirstLogon | Первый вход после установки; часть действий требует администратора |
| UserOnce | Первый вход каждого пользователя, не однократная настройка всего ПК |

## Группы возможностей (не список рекомендуемых включений)

- Регион/языки/раскладки; язык UI должен быть доступен в образе.
- Windows PE: интерактивно или генерируемый CMD; образ по имени/индексу,
  выбор диска, GPT/MBR, EFI/WinRE, собственный DiskPart, паузы, файл подкачки.
- Архитектуры, имя, часовой пояс, локальные пользователи/первый вход и политики.
- Проводник, Пуск/панель, визуальные эффекты, доступность и персонализация.
- Системные настройки, виртуализация и гостевые инструменты, Wi-Fi, privacy.
- Удаление компонентов, сценарии четырёх контекстов, AppLocker и XML-компоненты.
- Импорт результата этого сервиса, пресеты, просмотр/скачивание/закладка выбора.

При отборе диска по критериям автор требует ровно одно совпадение; иначе
остановка. Это не основание отключать проверку цели. Интерфейс различает выбор
образа/ключ установки и ключ активации. Название «Enterprise» не доказывает,
что выбран именно IoT Enterprise LTSC: проверять реальное содержимое образа.

## Шаблон карточки блока

ID/название/позиция/версия → назначение → все поля и варианты (включая условные)
→ последствия/механизм → применимость к станции/ОС/назначению → ветвление →
зависимости → рекомендация → решение владельца/основание → реализации →
проверки → текущие цель/критерии → открытые вопросы → три оси статуса.

Подшаг алгоритма содержит выбор и обоснование, точные действия и ссылки на
подробности. Для дополнительного сценария — отдельный подшаг реализации.
Не называть обзор группы разбором всех её полей. На каждый блок — отдельный
цикл согласования, даже если решение «оставить по умолчанию».
