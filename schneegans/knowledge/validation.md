# Сквозные проверки и сравнение

## До генерации

Реестр охватывает все блоки и условные поля; решения имеют подтверждение;
ветви и открытые зависимости видимы; текущие цель/критерии сформулированы;
существенно открытая конфигурация отмечена экспериментальной, не установочной.
Не путать три оси статусов из [регламента](../workflow.md).

## Сравнение двух кандидатов

| Проверка | Что установить |
|---|---|
| Происхождение | Ревизия решений, дата/коммит, ветвь, источник файла, хэш |
| Покрытие | Нет пропущенных решений или неожиданных добавлений |
| Семантика | Отделены формат/атрибуты/комментарии от функциональных различий |
| Проходы/контексты | Порядок, пользователь, права, область HKLM/HKCU/DefaultUser |
| Разрушительное | Цель диска, форматирование, удаление и условия остановки |
| Скрипты | Извлечение, пути, зависимости, ожидание, коды/ошибки, журнал |
| Безопасность | Секреты, остаточные файлы, защита и небезопасные умолчания |
| Недостаточность | Необработанные условия, отсутствие контроля результата |
| Избыточность | Повторы/задачи/конфликты с другими процедурами |
| Среда | Конкретный образ, редакция, компоненты, Ventoy/Setup |

По каждому функциональному расхождению: риск/основание → вариант сайта /
вариант агента / переработать оба / открытый вопрос → подтверждение → новая
ревизия. Совпадение двух XML не доказательство правильности общей спецификации.

## Практика (пока требует проверки)

XML well-formed ≠ валидация относительно образа ≠ безопасные скрипты ≠
работающая установка. При необходимости использовать Windows SIM с подходящим
образом/каталогом; затем контролируемое испытание. VM — предварительная
проверка, не подтверждение физического выбора диска/драйверов. Никакой тест
сам по себе не разрешает уничтожение исходников.

По S02 журналы: в PE — setupact.log/setuperr.log в X:\Windows и
X:\$WINDOWS.~BT\Sources\Panther; после перезагрузки — Windows\Panther;
скрипты — Windows\Setup\Scripts (Specialize/DefaultUser/FirstLogon),
UserOnce — пользовательский TEMP. Реальные буквы/пути уточнять на месте.
Фиксировать ожидаемое, фактическое, код/лог, среду, ограничения, подтверждение;
секреты редактировать перед публикацией. Результат не угадывать по завершению UI.

## Ревизия

В `metadata.md`: ID/предыдущая версия, дата, источники/коммит, принятые решения,
ветвь, хэши, происхождение, обезличивание. `site.xml` — неизменённый результат
сайта; `agent.xml` — самостоятельный кандидат; `comparison.md` — решения по
расхождениям; последующие кандидаты — в новых ревизиях; `checks.md` — реальные
результаты. Если артефакт не получен, не создавать файл-притворство.
