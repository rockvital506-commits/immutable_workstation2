# B05 — Setup settings

**Решение:** частично; владелец выбрал включение обхода требований, с просьбой
поправить предположение «никак не мешает». **Реализация:** XML не получен.
**Проверка:** требует проверки практикой.

## Первое поле — Bypass Windows 11 requirements check

Повторно проверен [Bypass.cs](https://github.com/cschneegans/unattend-generator/blob/27237f82e9a8498d9c5bab7d398dc34b7682a1e8/modifier/Bypass.cs)
2026-10-24. Обход создаётся **только для DefaultPESettings** при включённом
BypassRequirementsCheck: LabConfig BypassTPMCheck, BypassSecureBootCheck,
BypassRAMCheck = 1 в windowsPE. Не включает TPM/Secure Boot и не отключает их
сам по себе; не проверяет готовность оборудования. Не обещать обход всех проверок.

У нас выбран generated CMD, а не DefaultPESettings. Поэтому при сохранении B02
этот обход по изученному коду **не добавляется**, независимо от видимого флажка.
Зафиксировано желание владельца включить опцию, но для действующего механизма
она неприменима; не менять B02 и не добавлять собственный обход ради флажка.
Предположение об универсальной безвредности уточнено: в штатной ветви пропуск
проверок может убрать раннее предупреждение о неподходящей конфигурации.
Самостоятельный сетевой bypass — отдельное следующее поле, не это решение.

**Цель подшага:** согласовать настройки установки без неявной смены PE-механизма.
**Критерии:** активные параметры соответствуют B02; отсутствует несогласованный
собственный обход; влияние условных полей описано, а не объявлено реализованным.
При сравнении XML проверить, что сайт/агент трактуют ветвь одинаково. Если версия
генератора изменит область действия, вернуться к анализу, не молча переносить.
Практика не выполнялась. Для прошедшей проверки изменение неприменимо, для
будущей установки возможно. Остальные поля B05 пока не приняты.


## Второе поле — установка без интернета, ревизия решения 2

Владелец подтвердил **установку без интернета** и **Allow Windows 11 to be
installed without internet connection — включено**, запросил риски.
По pinned Bypass.cs Configuration.BypassNetworkCheck независимо от типа PE
добавляет в SpecializeScript запись DWORD BypassNRO=1 по пути
HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\OOBE. Это отличается от
аппаратного bypass, ограниченного DefaultPESettings. Собственного скрипта не
требуется. Это разрешение офлайн-прохождения, не отключение адаптеров/интернета,
не создание пользователя и не запрет будущих обновлений.

**Риски/зависимости:** действие OOBE зависит от фактического образа/сборки и
редакции; флажок не гарантирует полностью автоматическое прохождение (форма
предупреждает о ручном «У меня нет интернета»). Отдельно согласовать User accounts
в B08. Во время офлайн-установки не получаются сетевые обновления/драйверы и
обновления защиты; это не повод полностью блокировать WU. Успех офлайн-этапа
не доказывает готовность сети или актуальность системы перед её подключением.
Заранее учесть доступность нужных файлов/драйверов по согласованным процедурам;
новую загрузку/driverpack сейчас не назначать. Наличие интернет-кабеля/Wi-Fi
флажок физически не контролирует, сетезависимые дополнительные сценарии
должны быть исключены или отдельно согласованы.

**Критерии интеграции:** BypassNRO в specialize, отсутствие противоречащих
настроек в ответе/скриптах, возможность завершить OOBE без сети с согласованной
учётной записью; локально доступны необходимые для установки зависимости.
Изменение после установки: подключение к интернету возможно, пройденный OOBE
не меняется задним числом. CMD/XML ещё не получены, практика не выполнялась,
требует проверки практикой. Решение не является допуском к запуску.
Следующее поле — Use a distribution share / configuration set; ещё не выбрано.


## Уточнение границ работы владельцем

WinNTSetup сейчас **не рассматриваем**. Продолжаем последовательный разбор
генератора и его файла ответов. Способ доставки и использования ответа
согласуем позже: ни Ventoy AutoInstall, ни WinNTSetup не считать выбранными.
Не запрашивать версию WinNTSetup и не приостанавливать B05 ради его исследования.
Ранее принятый механизм B02 в спецификации генератора сохраняется; не объявлять
его пересмотренным или отменённым из-за обсуждения возможного способа запуска.
Это не подтверждает совместимость с любым будущим способом применения ответа.

Для поля Use a distribution share / configuration set сейчас объясняем
назначение и решаем потребность в дополнительном наборе файлов. Конкретные
пути, доступность $OEM$ и обработка будущим механизмом остаются отложенной
интеграционной проверкой. Рекомендация не включать без установленной потребности
сохраняется; согласия владельца на значение этого поля ещё нет.


## Configuration set — отложенное решение, обязательный возврат

Владелец явно оставил **Use a distribution share / configuration set** открытым
с обязательным возвратом позже. Не считать выключенным по рекомендации и не
считать включённым. Шесть примеров использования были иллюстрациями, не выбором
доставляемых файлов или дополнительных сценариев.

**Контроль возврата:** после разбора блоков и выявления внешних файлов/зависимостей,
а также при согласовании способа доставки/применения ответа. До окончательной
фиксации спецификации и генерации двух кандидатов вопрос должен быть закрыт
явным решением владельца. Проверить необходимость $OEM$, перечень и назначения
файлов, отсутствие секретов/коллизий со сценариями генератора, механизм копирования
и стадию применения. Если потребности нет — согласовать выключение, не принять
его молча. Открытый вопрос не блокирует последовательный разбор остальных полей.
Следующее поле B05 — Hide any PowerShell windows during Windows Setup.


## Сквозной учёт configuration set / $OEM$

Владелец уточнил: не только вернуться к отложенному полю в конце, но **учитывать
возможность $OEM$ при разборе и рекомендациях других настроек**, где есть связь.
При потребности во внешних сценариях, драйверах, установщиках, конфигурациях,
ресурсах или документации сравнивать штатный механизм/встраивание в ответ с
доставкой через $OEM$. Объяснять, что копируется, куда, когда и каким отдельным
действием применяется; учитывать контекст пользователя, офлайн-доступность,
секреты и коллизии с файлами генератора. Существование альтернативы не означает,
что она нужна или уже согласована. Не навязывать $OEM$ несвязанным полям.

Зависимости и аргументы записывать в карточке затронутого блока со ссылкой на
[B05](B05-setup.md); решение о включении и состав файлов остаются открытыми.
Если выбранная настройка действительно требует такого способа доставки,
вынести зависимость на согласование сразу, не ждать финальной сверки.
Способ доставки/применения ответа этим не выбран. Обязательный возврат до
финальной спецификации и генерации кандидатов сохраняется.
