# B02 — Windows PE stage

**Решение:** частично согласовано: генерируемый сайтом CMD для Windows PE.
Остальные поля B02 рассматриваются последовательно. **Реализация:** CMD/XML
ещё не получены. **Проверка:** требует проверки практикой. B01 согласован
как фиксированный набор; он не предопределяет остальные поля B02.

Источники: [S01](../../../sources.md), повторно прочитаны части формы 4–5
2026-10-24; [Disk.cs](https://github.com/cschneegans/unattend-generator/blob/27237f82e9a8498d9c5bab7d398dc34b7682a1e8/modifier/Disk.cs).
Ни кандидата XML, ни выполнения PE пока нет. Таблица охватывает поля блока,
включая альтернативные режимы, не означает их одновременное применение.

## Важные различия механизмов

В штатной ветви — windowsPE-компоненты Setup; в generated CMD — собственное
развёртывание DISM /Apply-Image, bcdboot и reboot. Ручной ввод номера **диска**,
ручной ввод **индекса образа** и интерактивный **DiskPart** — три разных решения.
Автоотбор по нескольким критериям должен дать ровно один диск; иначе остановка.
Критерии действуют только в своей ветви, не защищают произвольный custom CMD.

Буквы рабочего скрипта не тождественны окончательному C: установленной Windows.
Не приравнивать штатную PE установщика к Strelec; PowerShell обычно отсутствует,
а наличие нужных зависимостей скрипта проверяется отдельно.

## Связи с билдом

- B01: не навязать язык/регион последующим XML или PE-сценарием.
- B03: выбор образа и активация различаются; specialize ProductKey не доказательство
  правильной редакции на ранней стадии. OEM Home не новая лицензия IoT LTSC.
- B04/B05: архитектура, режим установки, bypass, ресурсы и configuration set.
- B13/B17/B24: защита, виртуализация, удаление и подкачка не должны конфликтовать.
- B25/B27: дополнительные элементы только после принятия необходимости.
- Ventoy и старые алгоритмы: уже есть выбор диска переменной и разметка. Не
  применять их параллельно с генерируемым wipe/DISM. Определить одного владельца
  разметки, выбора образа и boot files. Никаких запусков для выяснения вслепую.

## Рекомендация и запрос решения

Сначала выбрать **механизм PE**, затем его активные поля. Для первого кандидата
MSI рекомендация — штатная интерактивная PE: меньше новой логики, визуальный
контроль диска. Но она не решает автоматически риск OEM-ключа, требует проверки
выбора именно IoT LTSC и согласования разметки. Альтернатива generated CMD —
обоснована, если нужен управляемый отбор диска/образа и автоматическое развёртывание.
Полностью собственный CMD сейчас преимуществ не доказал.

Никакой режим пока не выбран; цель/критерии подшага будут уточнены после решения.
Ожидаемые направления проверки: правильный образ, единственная подтверждённая
цель диска, выбранная схема/WinRE, загрузка, сохранение B01, отсутствие
несогласованного отключения защиты. Установка и разметка не разрешены.
