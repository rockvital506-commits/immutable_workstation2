# autoinstall/ — механика плагина `auto_install`

Каталог описывает, **как работает плагин** Ventoy, подсовывающий установщику
файл ответа, не изменяя ISO.

> **База пути.** Непомеченные пути в этом документе считаются от корня
> репозитория. Префиксы `CONVENTIONS.md` §10.1 применяются там, где путь
> указывает на раздел флешки.

## Файлов ответа здесь нет — и быть не должно

> **Файлы `autounattend.xml` лежат в каталоге сборки**
> (`builds/<Станция>/answer/`), а не здесь. Правило — `CONVENTIONS.md` §6.

Каждая сборка уникальна: файл обязан учитывать накопитель станции, конкретный
образ и ТЗ заказчика. Общий шаблон не может учесть ни одного из трёх, а
положенный сюда применялся бы к чужим станциям.

Раньше в этом каталоге планировались `autounattend.xml`,
`autounattend-ltsc.xml` и `diskpart-256gb.txt`. Ни один не создан, и создавать
не нужно: разметка задаётся `DiskConfiguration` внутри прохода `windowsPE`,
отдельный файл `diskpart` плагином не используется.

## Привязка в ventoy.json

```json
"auto_install": [
    { "parent": "/ISO/windows",
      "template": "/builds/<Станция>/autounattend.xml" }
]
```

Точный путь и состав правок — **шаг 6 `algorithm.md`** конкретной сборки.

## Правила, выведенные из дефектов Ventoy

### 1. Только `parent`, не `image`

Сопоставление по `"image"`, включая маски вида `/ISO/windows/*.iso`, не
срабатывает — меню выбора файла ответа не появляется. По `"parent"` работает
штатно (`research/02`, K3; discussion #3002).

### 2. Не задавать ни `timeout`, ни `autosel`

Семантика по официальной документации:

| `timeout` | `autosel` | Поведение |
|-----------|-----------|-----------|
| > 0 | любой | меню появляется, по истечении выбирается пункт |
| = 0 | любой | меню появляется и ждёт выбора вечно |
| не задан | задан | **меню не появляется, шаблон применяется сразу** |
| не задан | не задан | то же, что `timeout = 0` |

Нам нужен последний режим — ожидание выбора. Поэтому не задаётся **ни один** из
ключей. Правило «не задавать timeout» неполное: при `autosel` шаблон уходит в
применение без спроса (`research/16`, N5).

### 3. Файл обязан называться `autounattend.xml`

Иначе установщик Windows его не подхватит. В каталоге сборки файлы носят
описательные имена и переименовываются при копировании.

### 4. НЕ класть файл в корень флешки

Дефект Ventoy 1.1.05 (issue #3168): файл ответа в корневом каталоге применяется
ко всем ISO, и отказаться от него нельзя — даже при пустом `auto_install`.
Лечится только размещением в отдельном каталоге (`research/16`, N3).

### 5. Файл обязан содержать проход `windowsPE`

Ventoy раскладывает шаблон как `X:\autounattend.xml`. Setup кэширует файл
ответа только при наличии валидных настроек **текущего прохода**. Без секции
`windowsPE` файл не кэшируется, и установка молча уходит в ручной режим — ни
ошибки, ни подсказки (`research/16`, N1).

### 6. Диск — только переменной `$$VT_…$$`

Документация Ventoy формулирует риск прямо: жёстко заданный `DISK0` «может
установить ОС на неверный диск или даже на диск, где расположен Ventoy».
Файл с переменными обязан быть в UTF-8 (`research/16`, N2).

| Переменная | Смысл |
|------------|-------|
| `$$VT_WINDOWS_DISK_1ST_NONVTOY$$` | Первый диск, не являющийся Ventoy |
| `$$VT_WINDOWS_DISK_NONVTOY_CLOSEST_XXX$$` | Не-Ventoy диск, ближайший к XXX ГБ |
| `$$VT_WINDOWS_DISK_MAX_SIZE$$` | Наибольший диск. Опасно при подключённом внешнем носителе |

## Как проходит загрузка

1. Ventoy → выбор ISO.
2. Появляется второй экран с пунктом «boot with `<путь>`» — выбрать его явно.
   Обычная загрузка ISO остаётся доступной: это способ поставить систему
   вручную, если шаблон не сработал.
3. Установщик читает `autounattend.xml` и идёт без запросов.

## Если шаблон не применился

Диагностика начинается **не** с правки файла:

1. `C:\Windows\Panther\unattend.xml` — существует ли и наш ли он. Чужой
   `autounattend.xml` (от Rufus или Ventoy) выше в порядке поиска и молча
   перекрывает наш (`research/16`, N4).
2. `F5 → Tools menu → Check plugin json configuration (ventoy.json)` —
   распознан ли блок `auto_install`.
3. Кодировка файла: переменные `$$VT_…$$` раскрываются только в UTF-8.
4. Режим загрузки: при `memdisk` поведение отличается от обычного.

## Ограничение

Плагин работает для Windows и части Linux-дистрибутивов (kickstart/preseed).
Для Linux Mint Live-загрузки не применяется — там используется
[`../persistence/`](../persistence/).

## Не проверено на месте

| Пункт | Что нужно |
|-------|-----------|
| Распознавание блока `auto_install` нашей версией Ventoy | Версия Ventoy на флешке не зафиксирована |
| Повторное появление меню выбора после правки `ventoy.json` | Требует загрузки с флешки |
| Дефект с файлом в корне | Описан для Ventoy 1.1.05, на нашей версии не воспроизводился |
