# builds/ — станционно-специфичные сборки

Каталог для всего, что относится **только к конкретной станции** и не является
универсальным. Универсальное — в `ISO/` (образы) и на разделе `Tools` (утилиты).

Правило: `builds/<Производитель>_<Модель>_<ЦелеваяОС>/`.

| Каталог | Станция | Целевая ОС |
|---------|---------|-----------|
| `MSI_B12M-211RU_Win11_LTSC_IoT_24H2/` | MSI Modern 15 B12M-211RU | Windows 11 IoT Enterprise LTSC 2024 |

## Соглашение об имени

`builds/<Производитель>_<Модель>_<ЦелеваяОС>` — латиница, `_` как разделитель,
полностью соответствует `CONVENTIONS.md`, раздел 1.

## Что лежит внутри станционного каталога

```
builds/<станция>/
├── README.md           паспорт станции и статус работ
├── drivers/            экспорт драйверов + INF-пакеты (заглушки для бинарных)
├── answer/             autounattend.xml и связанные шаблоны
├── config/             эталонные конфиги: политики, реестр, планировщик
├── scripts/            станционные скрипты (.ps1 + .sh)
├── backup/             место под образы и дампы этой станции
└── reports/            отчёты: аудит до/после, SMART, логи enforcement
```

## Что сюда класть НЕ нужно

- Универсальные утилиты → раздел `Tools`.
- Дистрибутивы ОС → `ISO/windows/`.
- Аварийные среды → `ISO/winpe/`.
- Данные заказчика (документы, пароли) → только в `backup/` и только на время работ.
