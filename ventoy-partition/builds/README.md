# builds/ — станционные сборки

Каталог на каждую конкретную машину, с которой велась работа. Здесь живёт
только то, что относится **исключительно к конкретной станции**.
Универсальное — в `ISO/` (образы) и в `tools/` (утилиты).

## Именование

`<Вендор>_<Модель>_<ОС>_<Версия>`

Пример: `MSI_B12M-211RU_Win11_LTSC_IoT_24H2`.

## Правило algorithm.md

> **Для каждого билда каждой станции обязателен файл `algorithm.md`** — он
> описывает весь цикл от живой ОС до валидации развернутой системы, включая
> статусы сети для каждого шага (критично для защиты от телеметрии до её
> блокировки), плюс инструкции и рекомендации по дальнейшей эксплуатации.

Шаблон: `_templates/algorithm.md`. Отсутствие файла — ошибка валидации,
коммит блокируется.

## Структура каталога станции

```
<Станция>/
├── algorithm.md      полный цикл работ, статусы сети, валидация, эксплуатация
├── README.md         паспорт станции
├── drivers/          выгруженные и скачанные драйверы
├── answer/           autounattend.xml и ответы установщика
├── config/           политики, .reg-файлы отката
├── scripts/          станционно-специфичные скрипты
├── backup/           копии профилей и настроек этой станции
├── reports/          отчёты диагностики и валидации
└── drivers|answer|... пустые каталоги держатся файлом .keep
```

## Состав

## Служебные каталоги

| Каталог | Назначение |
|---------|-----------|
| `_templates/` | Шаблоны документов станции. Станцией не считается, правилу `algorithm.md` не подчиняется |

## Что сюда класть НЕ нужно

- Универсальные утилиты → `tools/`.
- Дистрибутивы ОС → `ventoy-partition/ISO/windows/`.
- Аварийные среды → `ventoy-partition/ISO/winpe/`.
- Данные заказчика (документы, пароли) → только в `backup/` конкретной станции
  и только на время работ.
