# answer/ — файлы ответа станции

Файлы `autounattend.xml` для автоматической установки. Лежат **в каталоге
сборки**, а не в общем `ventoy/autoinstall/`: каждый файл учитывает накопитель
станции, конкретный образ и ТЗ владельца (`CONVENTIONS.md` §6).

> **База пути.** Непомеченные пути в этом документе считаются от корня
> репозитория. Префиксы `CONVENTIONS.md` §10.1 применяются там, где путь
> указывает на раздел флешки.

## Состав

| Файл | Когда применять |
|------|-----------------|
| `autounattend-ltsc-2024.xml` | **Основной.** Целевая станция MSI B12M-211RU: i3-1215U, TPM 2.0, 8 ГБ, NVMe 256 ГБ. Обхода требований нет |
| `autounattend-ltsc-2024-bypass.xml` | Тот же состав плюс обход проверок TPM, Secure Boot, памяти, места и процессора (`LabConfig`). Для «зоопарка» железа, когда LTSC 2024 ставится на неподдерживаемую станцию |

Обход вынесен в отдельный файл решением владельца: чистая установка на
поддерживаемом железе не должна нести в себе обход, иначе потом непонятно,
была ли станция поддержана изначально.

## Различия между файлами

| Что | Основной | С обходом |
|-----|----------|-----------|
| Проход `windowsPE` | есть | есть |
| `LabConfig` (5 значений) | нет | есть |
| Переменная выбора диска | `$$VT_WINDOWS_DISK_NONVTOY_CLOSEST_256$$` | `$$VT_WINDOWS_DISK_1ST_NONVTOY$$` |
| Разметка GPT | 500 / 260 / 128 / остаток | та же |
| Локальная учётная запись | `user`, пустой пароль | та же |

Переменная выбора диска различается намеренно: на целевой станции накопитель
известен (NVMe 256 ГБ), поэтому берётся ближайший к 256 ГБ не-Ventoy диск; на
произвольном железе накопитель может быть любым, поэтому берётся первый
не-Ventoy.

## Три правила, без которых файл не сработает

1. **Проход `windowsPE` обязателен.** Ventoy раскладывает шаблон как
   `X:\autounattend.xml`; без валидных настроек текущего прохода Setup не
   кэширует файл, и установка молча уходит в ручной режим. Ни ошибки, ни
   подсказки (`research/16`, N1).
2. **Кодировка UTF-8.** Раскрытие переменных Ventoy требует UTF-8. BOM не
   нужен, переводы строк — LF.
3. **Диск — только переменной `$$VT_…$$`.** Жёстко заданный `<DiskID>0</DiskID>`
   может поставить ОС на флешку Ventoy — документация Ventoy формулирует этот
   риск прямо (`research/16`, N2).

## Ключ продукта: ключ из прошивки игнорируется

В обоих файлах в проходе `specialize` явно задан `ProductKey`:

```xml
<ProductKey>KBN8V-HFGQ4-MGXVD-347P6-PDQGT</ProductKey>
```

Зачем это нужно. В прошивке станции зашит ключ предустановленной Windows 11
Home (OEM:OA3, в ACPI-таблице MSDM). Если ключ в файле ответа не задавать,
установщик может подхватить его из прошивки. Для IoT Enterprise LTSC он не
подходит ни по редакции, ни по каналу лицензирования.

Значение взято из официальной таблицы Microsoft — это GVLK (KMS-клиентский
ключ) для Windows IoT Enterprise LTSC 2024
(`learn.microsoft.com/windows-server/get-started/kms-client-activation-keys`).

Три вещи, которые надо понимать:

| Факт | Следствие |
|------|-----------|
| GVLK лицензией не является | Система после установки не активирована, и это ожидаемо |
| GVLK указывает редакции искать KMS-узел | В домашней сети KMS-узла нет, активация не произойдёт сама |
| Ключ задан в `specialize`, а не в `windowsPE` | При ключе в `windowsPE` OOBE начал бы запрашивать ключ у пользователя |

Активация выполняется отдельным шагом алгоритма — шаг 12, после появления
сети. Там же описана отвязка Retail-ключа от предыдущей станции.

**Не проверено:** какой ключ фактически зашит в прошивку этой станции — он не
читался. Проверить: `wmic path SoftwareLicensingService get OA3xOriginalProductKey`.

## Минимальная версия Ventoy — 1.1.11

Переменная `$$VT_WINDOWS_DISK_NONVTOY_CLOSEST_XXX$$` добавлена в плагин
AutoInstall в релизе **1.1.11** (2026-04-05). На Ventoy старше она не
раскроется, и `DiskID` получит мусорное значение — установка уйдёт не туда или
упадёт. Проверить версию до установки:

```
F2 → About, или Ventoy2Disk.exe покажет версию при запуске
```

Наш `ventoy.json` дополнительно содержит `VTOY_SECURE_BOOT_POLICY` — эта опция
появилась в 1.1.14, поэтому фактический минимум для флешки — **1.1.14**.
Рекомендуемая версия — 1.1.18 (релиз 2026-10-09).

**С 1.1.14 Ventoy использует новый shim, подписанный UEFI CA 2023.** При первой
загрузке после переустановки Ventoy новый ключ нужно записать (enroll) — на
станции с включённым Secure Boot без этого флешка не загрузится, и это легко
принять за неисправность носителя.

## Куда положить на флешке

**Не в корень.** Файл ответа в корневом каталоге применяется ко всем ISO и
отказаться от него нельзя (дефект Ventoy 1.1.05, issue #3168).

Каталог и точные правки `ventoy.json` — **шаг 6 `algorithm.md`**. Здесь
намеренно не дублируется: инструкция обязана быть в одном месте.

## Имя файла при копировании

В каталоге сборки файлы носят описательные имена. На флешку файл копируется
под именем `autounattend.xml` — иначе установщик Windows его не подхватит.

## Откат

Файл ответа ничего не меняет до начала установки, поэтому откат — это отмена
установки до перезаписи разделов. После `WillWipeDisk = true` данные накопителя
уничтожены: точка невозврата — начало установки, а не её завершение. Именно
поэтому шаг 2 алгоритма (первоначальный бэкап) идёт раньше шага 6.

## Не проверено на месте

| Пункт | Что нужно |
|-------|-----------|
| Оба файла | Ни разу не применялись к реальному установщику |
| Раскрытие `$$VT_WINDOWS_DISK_NONVTOY_CLOSEST_256$$` | Требует загрузки с Ventoy на реальном железе |
| Редакция внутри `install.wim` образа LTSC 2024 | Образов на флешке нет, все ISO — заглушки; если редакций несколько, нужен `InstallFrom`/`MetaData` |
| Пустой пароль в `<Password><Value></Value>` | Поведение установщика 24H2 при пустом значении не проверено |
| `SetupPrep.exe` в 24H2 | Для 24H2 установщик вызывает его; несовместимость описана для встраивания файлов в XML, у нас встраивания нет |
| Часовой пояс `Russian Standard Time` | Точное имя не сверено со списком `tzutil /l` |
