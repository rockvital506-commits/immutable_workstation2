# 07. Механизмы блокировки, зачистки, удушения, декорации и перенаправления

**Фильтр применимости (требование заказчика):** исключены механизмы, требующие
подписанного драйвера и несущие риск BSOD. Поэтому в перечне **нет**:
фильтрующих драйверов файловой системы (minifilter), драйверных callback'ов
(`ObRegisterCallbacks`, `PsSetCreateProcessNotifyRoutine`), подмены HAL/ядра,
патчинга `ntoskrnl`, Hyper-V-уровневых перехватов.

Все перечисленные механизмы работают в user-mode или через штатные настройки ОС.

---

## M1. Image File Execution Options (IFEO) — перенаправление и заглушка

**Принцип.** Ключ `...\Image File Execution Options\<имя.exe>\Debugger` заменяет
запуск целевого файла запуском указанного, передавая исходную командную строку
аргументом (E1).

**Варианты применения:**

| Вариант | Значение `Debugger` | Эффект |
|---------|--------------------|--------|
| Глухая заглушка | `%SystemRoot%\System32\systray.exe` | Процесс «запускается» и сразу завершается, ничего не делая |
| Логгер | Свой бинарник/скрипт, пишущий дату, путь, аргументы | Видно, **кто и когда** пытался запустить |
| Декоратор | Обёртка, проверяющая аргументы и решающая, запускать ли оригинал | Точечный запрет команды (паттерн P6) |
| Блокиратор службы | `svchost.exe` | SCM получает ошибку запуска службы (E7) |

**Сильные стороны:** нулевая стоимость, мгновенный откат (`reg delete`),
не требует перезагрузки, работает для 32/64-бит.

**Ограничения:**
- сопоставление **только по имени файла**, маски невозможны; для путей —
  `UseFilter` (тоже без масок) (E4);
- обход через `CreateProcess` с `DEBUG_PROCESS` (E3) → не security-механизм;
- требует HKLM/админ-прав (E5);
- **не** глушить `WerFault.exe` глобально — на нём работает `SilentProcessExit`.

**Когда применять:** телеметрия-исполнители (`CompatTelRunner.exe`,
`wsqmcons.exe`, `DmClient.exe`), OEM-агенты с известными именами EXE.

## M2. Silent Process Exit (GlobalFlag 512) — триггер по завершению

**Принцип.** `...\IFEO\<exe>\GlobalFlag = 512` +
`...\SilentProcessExit\<exe>\{ReportingMode=1, MonitorProcess=<payload>}` —
payload стартует при завершении целевого процесса, родителем выступает
`WerFault.exe` (E6).

**Применение у нас:** не для блокировки, а для **наблюдения** — фиксация факта
завершения агента (диагностика «мусор перезапускается сам»).

---

## M3. Локальные групповые политики (GPO) — штатный запрет

**Принцип.** Значения в `HKLM\SOFTWARE\Policies\Microsoft\...` имеют приоритет
над обычными ключами и применяются системой.

| Задача | Политика / ключ |
|--------|-----------------|
| Телеметрия | `Policies\Microsoft\Windows\DataCollection\AllowTelemetry = 0` (для Enterprise/LTSC; см. конфликт D9) |
| Аппаратная телеметрия | `Policies\Microsoft\Windows\AppCompat\{AITEnable=0, DisableInventory=1, DisableUAR=1}` |
| CEIP | `Policies\Microsoft\SQMClient\Windows\CEIPEnable = 0` |
| Потребительские функции | `Policies\Microsoft\Windows\CloudContent\DisableWindowsConsumerFeatures = 1` |
| Драйверы из WU | `ExcludeWUDriversInQualityUpdate` (GPO, с 1607) |
| Запрет устройств по ID | `Policies\Microsoft\Windows\DeviceInstall\Restrictions\DenyDeviceIDs` + `DenyDeviceIDsRetroactive=1` |
| Запрет по классу устройств | `DenyDeviceClasses` (GUID класса) |
| Не искать драйверы в интернете | «Задать порядок поиска драйверов» → «Не искать на веб-сайте Центра обновления» |
| Запрет метаданных устройств | `Prevent device metadata retrieval from the Internet` |
| Доступ к WU | «Запретить доступ для использования любых средств Центра обновления Windows» |

**Инструмент переноса в рабочей группе:** `LGPO.exe` (копирование локальных
политик между машинами).

**Сильные стороны:** поддерживаемый механизм, переживает обновления, виден в
`gpedit.msc` — заказчику понятно, что сделано.
**Ограничение:** политика перекрывает обычную правку реестра — при отладке
сначала проверять наличие политики.

## M4. Файл hosts — сетевое перенаправление

**Принцип.** `C:\Windows\System32\drivers\etc\hosts` резолвится раньше DNS.

**Применение:** перенаправление доменов телеметрии и автообновления в `0.0.0.0`.

**Ограничения:**
- работает только для приложений, использующих штатный резолвинг;
- **не** действует на трафик с жёстко зашитыми IP;
- не действует на HTTPS-сертификаты (соединение упадёт, а не перенаправится);
- легко обходится приложением, читающим DNS напрямую.

**Роль:** дешёвый дополнительный слой, **не** основной. Основное — M5.

## M5. Windows Defender Firewall — исходящие правила

**Принцип.** Запрет исходящего трафика по исполняемому файлу — самый надёжный
user-mode способ «ослепить» агент.

```powershell
New-NetFirewallRule -DisplayName "BLOCK <agent>" -Direction Outbound `
    -Program "C:\Windows\System32\<agent>.exe" -Action Block -Profile Any
```

**Сильные стороны:** работает независимо от резолвинга, виден в штатной оснастке,
мгновенный откат `Remove-NetFirewallRule`.

**Применение:** агенты OEM, Edge Update, службы, которые нельзя отключить.

**Осторожно:** блокировать `svchost.exe` целиком нельзя — через него идёт
системный трафик; только точечно по службе (`-Service`).

## M6. ACL Deny — запрет прав на файл или ключ

**Принцип.** `icacls <путь> /deny "*S-1-5-32-544:(RX)"` или
`Set-Acl` — запрет чтения/исполнения даже администраторам и SYSTEM.

**Применение:**
- запрет запуска конкретного EXE (Deny `Execute`);
- запрет перезаписи нашего конфига агентом;
- запрет чтения каталога с конфиденциальными данными.

**Сильные стороны:** работает на уровне ядра (NTFS/реестр), не обходится
user-mode-трюками, не требует драйвера.

**Риски:**
- Deny для SYSTEM может сделать объект неудаляемым без снятия ACL;
- обязательно хранить команду отката `/remove:d`;
- **не применять** к системным каталогам и boot-critical файлам — риск
  незагружаемости (не BSOD, но Recovery).

**Раздел `Tools` имеет NTFS → ACL доступны; на exFAT-разделе Ventoy их нет.**

## M7. Отключение/маскировка служб и задач

| Уровень | Команда | Обратимость |
|---------|---------|-------------|
| Тип запуска | `Set-Service X -StartupType Disabled` | `Set-Service X -StartupType Manual/Automatic` |
| Принудительная остановка | `Stop-Service X -Force` | `Start-Service X` |
| Задача планировщика | `schtasks /Change /TN X /Disable` | `/Enable` |
| Удаление задачи | `schtasks /Delete /TN X /F` | Пересоздание из эталона |
| Реестр службы | `HKLM\SYSTEM\CurrentControlSet\Services\X\Start = 4` | Вернуть исходное значение |

**Приоритет:** сначала задача (инициатор), потом служба (исполнитель) — паттерн P3.

## M8. Wrapper / бинарный декоратор обращений

**Принцип.** Оригинал переименовывается (`DISM.exe` → `DISM.real.exe`), на его
место кладётся наш исполнитель с тем же именем, который фильтрует аргументы и
либо блокирует вызов, либо делегирует оригиналу.

**Единственный механизм, способный запретить конкретную команду, сохранив
инструмент** (паттерн P6) — ни GPO, ни ACL, ни IFEO аргументы не различают.

**Требования к реализации:**
- идемпотентность установки/снятия;
- лог всех заблокированных вызовов с аргументами;
- прозрачная передача кода возврата оригинала;
- хранение оригинала вне зоны перезаписи обновлениями;
- явная команда `--restore` для мгновенного возврата.

**Ограничение:** обновления Windows могут восстановить оригинальный файл —
поэтому wrapper проверяется enforcement-задачей (P5).

**Важно:** переименование системного бинарника — вмешательство в состав ОС.
Для `DISM.exe` безопаснее **не** подменять системный файл, а держать wrapper
на флешке и вызывать его явно (`T:\scripts\wrappers\DISM.cmd`), зафиксировав в
регламенте. Подмена системного файла — только по явному решению заказчика.

## M9. Watchdog (сторожевой контроль)

**Принцип.** Периодическая проверка целевого состояния и возврат отклонений.

**Реализация:** задача планировщика от SYSTEM, старт +2 мин, далее каждые 6 часов
(паттерн P5).

**Проверяет:** типы запуска служб, состояние задач планировщика, наличие ключей
IFEO, значения политик, наличие записей в `hosts`, правила firewall, целостность
wrapper'ов.

**Выход:** лог отклонений + автоисправление. Лог — артефакт отчёта.

**Важно:** watchdog **сам** является задачей планировщика, то есть попадает под
риск отключения обновлениями → проверяет и себя.

## M10. Middleware / перехват на уровне приложения

**Принцип.** Промежуточный слой между вызывающим и целевым компонентом:
прокси, `AppInit_DLLs`, COM-перехват, подмена DLL в каталоге приложения (DLL
search order).

**Оценка для нашей задачи:**

| Подвид | Решение |
|--------|---------|
| `AppInit_DLLs` | **Не применять**: на x64 по умолчанию отключён (требует `LoadAppInit_DLLs`), подписанность, конфликт с Secure Boot |
| DLL search order hijack | **Не применять**: хрупко, ломается обновлениями, ассоциируется с вредоносными техниками |
| COM-перехват | **Не применять**: избыточно для задачи |
| HTTP(S)-прокси (локальный) | **Допустимо** для диагностики трафика, не для постоянной блокировки |

**Вывод:** из middleware в работу берётся только локальный прокси как
диагностический инструмент.

## M11. Перенаправление путей и «файлы-перенаправленцы»

**Принцип.** Замена реального файла/каталога на ссылку или пустышку.

| Приём | Команда | Применение |
|-------|---------|-----------|
| Junction на каталог | `mklink /J` | Перенос кэша/логов с системного диска (снижение записей на SSD) |
| Символическая ссылка на файл | `mklink` | Замена конфига агента на наш |
| Нулевой файл-заглушка | Создание пустого файла вместо ожидаемого | Агент не может создать свой конфиг |
| Read-only атрибут + ACL | `attrib +R` + M6 | Защита нашего конфига от перезаписи |

**Осторожно:** создание файла-заглушки вместо каталога, ожидаемого установщиком,
может привести к ошибке установки — проверять на тестовой машине.

---

## M12. Пессимизация (деградация вместо запрета)

**Принцип.** Не запрещать, а делать бессмысленным: лишить ресурса или права.

| Приём | Эффект |
|-------|--------|
| Запуск службы от учётной записи без прав | Служба стартует и падает |
| Ограничение квоты/приоритета | Агент работает, но не мешает |
| `Deny` на каталог данных агента | Агент не может писать телеметрию |
| Ограничение исходящего трафика правилом M5 на конкретный порт | Агент «слеп», но жив |

**Когда применять:** когда полное отключение ломает зависимую функциональность,
а шум убрать нужно.

## Сводная матрица выбора механизма

| Цель | Первый выбор | Второй | Третий |
|------|--------------|--------|--------|
| Запретить EXE телеметрии | M7 (задача) + M7 (служба) | M1 (IFEO-заглушка) | M5 (firewall) |
| Запретить конкретную команду инструмента | M8 (wrapper) | — | — |
| Запретить возврат драйверов из WU | M3 (GPO `ExcludeWUDriversInQualityUpdate`) | M3 (`DenyDeviceIDs`) | M5 |
| Ослепить OEM-агент | M5 (firewall по EXE) | M4 (hosts) | M6 (ACL на каталог данных) |
| Защитить конфиг от перезаписи | M6 (ACL Deny) | M11 (read-only) | — |
| Запретить установку UWP новым пользователям | `Remove-AppxProvisionedPackage` | M3 (`DisableWindowsConsumerFeatures`) | — |
| Не дать мусору вернуться после обновления | M9 (watchdog) | M7 + M1 | — |
| Снизить износ SSD | Настройки ОС (`powercfg`, pagefile, TRIM) | M11 (junction для кэша) | — |

## Порядок применения и обязательный аудит

1. **До** любых блокировок — полный дамп состояния (службы, задачи, Run, Active
   Setup, IFEO, GPO, ACL, WMI-subscriptions, firewall-правила).
2. Применять сверху вниз по матрице, останавливаясь при достижении цели.
3. Каждое действие — с сохранённой командой отката.
4. После — повторный дамп и diff.
5. Watchdog включается последним.
