# Role-aware composition: D04, core и границы нормативных артефактов

## 1. Критерии до кода

Владелец подтвердил47 и продолжение. Следующий bounded construct — единый
reviewable research draft, а не универсальная переносимость runtime и не выпуск.

Acceptance:

1. Связать внешний D04 из47 с точным source/17связанными единицами45. Требовать
   совпадения версии/hash/span, сохранить14preserved/3generalized groups, scope,
   meaning links и original contract. Не объявлять новый semantic review самим
   фактом совпадения source; прежние uncertainty/limitations не стираются.
2. Добавить C01–C10 и оставшиеся нормативные разделы ENT1r1, чтобы reviewable core
   не терял purpose, применение, проверку и stop-on-uncertainty. Требования
   сохраняются буквально; структура/заголовки не выдаются за дополнительные нормы.
3. Каждому из90артефактов declared closure назначить функциональную роль:
   rule source, component contract/procedure/prompt, implementation, verification,
   schema, fixture/descriptor, environment lock. Role не является universality
   grade: ни расширение файла, ни registry normative не доказывают универсальность.
4. Не помещать код/schema/fixtures/lock в общий rule text. Сохранить все90exact
   references в dependency composition; компонентные contracts/procedures/prompts
   оставить explicit semantic-review queue, не считать их смыслы ненужными.
5. Сохранить exact24revision closure, r1/r2 consumers и полный **известный** набор
   решений (все имена плоского ledger, не только approvals выбранных версий).
   Неизвестное/лишнее имя/изменение bytes не фильтровать. Snapshot не global freshness,
   не authentication решения владельца и не actual grant.
6. Собирать фактический draft из pinned bytes и уже предъявленных обобщений,
   не исполнять код инвентаря. Предъявить derived Markdown preview как предмет
   дальнейшей semantic review: не новый нормативный источник/active context.
7. Проверить source substitution, role laundering, пропущенную dependency,
   schema/code→rule injection, потерянный restriction/ledger entry, исключение
   формата под видом non-universal и self-attested completeness/authority.
8. Все G05semantic completeness/behavior/actual readiness gates остаются отдельны;
   unresolved references могут закрыться структурно, но не превращаются в
   доказательство семантической эквивалентности. Нет новой среды/активации/экспорта,
   новых normative registrations/approvals или сторонних dependencies.

## 2. Обоснование

Выигрыш —85разнородных «artifact gaps» заменяются проверяемой ролью и точной очередью
semantic review. D04 перестаёт быть несвязанной ссылкой; core предъявлен целиком.
Цена — хранить artifact composition отдельно от сокращённого rule view. Риск —
ошибочно приравнять функциональную роль к отсутствию универсального смысла;
поэтому component docs не отбрасываются, а code/schema не удаляются из состава.
