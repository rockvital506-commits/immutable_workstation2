# 03. Паттерны, методологии, архитектурные конструкты

Отфильтровано по критерию применимости: без подписанных драйверов, без риска BSOD,
реализуемо выездным мастером без вскрытия станции.

---

## P1. Паттерн «Реестр-зеркало с заглушками» (Repo-as-Truth)

**Суть.** Реальный носитель и репозиторий — два представления одной структуры;
расхождение считается дефектом и обнаруживается автоматически.

**Реализация у нас:** `scripts/check-flash.sh|.ps1` сравнивает ISO на флешке с
заглушками `*.iso.md`, группы на разделе TOOLS с `tools/`, сверяет SHA256 с
`manifest.csv`. Код возврата `1` при расхождении.

**Почему эффективен.** Устраняет «флешку-загадку»: любое изменение на носителе
либо описано, либо видно как отклонение.

---

## P2. Паттерн «Заглушка вместо бинарника»

**Суть.** В git — текст, на флешке — файл; связь через суффикс `.md`.
**Эффект:** репозиторий остаётся обозримым и переносимым, а состав флешки —
восстанавливаемым по URL и SHA256.

---

## P3. Паттерн «Приоритет инициатора» (для блокировок)

**Суть.** Блокировать надо **причину**, а не следствие: планировщик-триггер,
службу-активатор, ключ автозапуска — раньше, чем порождаемые ими процессы.

**Следствие для приоритетов:**
```
инициатор / будильник / активатор   >>   инициализируемый / будимый / активируемый
```
Пример: `Task Scheduler`-задача `Microsoft Compatibility Appraiser` (инициатор)
важнее процесса `CompatTelRunner.exe` (исполнитель). Отключив задачу, мы убираем
и запуск исполнителя; заглушив только исполнитель, оставляем работающий триггер.

## P4. Паттерн «Многослойное удушение» (Defence in Depth против мусора)

Ни один слой не даёт 100%, поэтому применяется связка по возрастанию цены отката:

| Слой | Механизм | Цена отката | Что закрывает |
|------|----------|-------------|---------------|
| 1 | Групповые политики (реестр `Policies`) | Удаление ключа | Штатно отключаемое: телеметрия, драйверы из WU, потребительские функции |
| 2 | Отключение задач планировщика | `schtasks /Change /Enable` | Таймерные инициаторы |
| 3 | `Set-Service -StartupType Disabled` | `sc config ... start= auto` | Службы-активаторы |
| 4 | Удаление appx + provisioned | Переустановка из Store/образа | Store-мусор и его возврат новым пользователям |
| 5 | IFEO `Debugger`-заглушка | Удаление ключа IFEO | Отдельные EXE, не отключаемые иначе |
| 6 | ACL Deny на файл/ключ | `icacls ... /remove:d` | Упорные агенты, пересоздающие себя |
| 7 | Hosts / firewall | Удаление строки/правила | Сетевые каналы телеметрии и автообновления |

**Правило применения:** идти сверху вниз и **останавливаться**, как только цель
достигнута. Нижние слои — только для того, что не закрылось верхними.

## P5. Паттерн «Enforcement-задача» (анти-самовосстановление)

**Суть.** Windows после обновлений возвращает часть отключённого. Вместо борьбы
с каждым случаем — собственная задача планировщика, которая периодически
возвращает целевое состояние и **пишет лог отклонений**.

**Параметры:** запуск от SYSTEM, при старте с задержкой ~2 мин и далее раз в
6 часов; идемпотентна; лог в файл; при каждом отклонении — запись «что вернулось».

**Ценность для выездного мастера:** лог — готовый артефакт для отчёта и
диагностики «почему мусор вернулся».

---

## P6. Паттерн «Точечный запрет вместо отключения инструмента»

Требование заказчика: запретить конкретную команду, сохранив инструмент.
Реализуется **не** блокировкой бинарника, а ограничением на уровне аргументов:

| Инструмент | Запретить | Разрешить |
|-----------|-----------|-----------|
| `DISM.exe` | `/RestoreHealth`, `/StartComponentCleanup`, `/ResetBase` | Всё остальное обслуживание |
| `powercfg` | `/hibernate on` | `/hibernate off`, `/a`, `/requests` |
| `fsutil` | `behavior set DisableDeleteNotify 1` | `behavior query ...` |
| `bcdedit` | `/set ... recoveryenabled No` без фиксации в реестре изменений | Чтение `/enum` |

**Механизм:** wrapper-исполняемый файл, перехватывающий вызов (см. `07-blocking-mechanisms.md`,
механизм M8 «Wrapper/бинарный декоратор»), либо IFEO с собственным фильтром
аргументов. **[вывод]** Это единственный способ запретить команду, не ломая
инструмент: ни GPO, ни ACL не различают аргументы командной строки.

## P7. Паттерн «Образ-эталон + дельта» (Golden Image + Delta)

**Суть.** Один раз собрать эталонную настроенную систему → зафиксировать образ
→ дальше разворачивать образ, а не настраивать вручную; все последующие правки —
дельтой поверх эталона.

**Применение:** после успешной миграции станции MSI создаётся эталон;
`Ventoy/builds/<станция>/` хранит **и** образ, **и** дельту (скрипты, драйверы,
ответы установки).

---

## P8. Паттерн «Контракт состояния сети для каждого шага»

**Суть.** Каждый шаг алгоритма миграции declares требуемое состояние сети:
`offline` / `online` / `online-ограниченный`. Это делает алгоритм
воспроизводимым и исключает «самопроизвольные» установки во время работы.

**Практическое следствие:** установка ОС и debloat идут в `offline`,
пост-проверка обновлений — в `online`, выгрузка образов — в `offline`.

---

## P9. Паттерн «Сначала экспорт, потом снос» (Export-Before-Destroy)

**Суть.** Любое разрушающее действие предваряется экспортом того, что теряется:
`DISM /Export-Driver` → потом разметка диска; бэкап профилей → потом удаление
учётных записей; `reg export` → потом правка политик.

**Обязательные пары «экспорт → действие»:**

| Экспорт | Действие после |
|---------|----------------|
| `DISM /Online /Export-Driver` | Разметка/установка ОС |
| Копия `User Data` Chrome, `%APPDATA%\Code` | Удаление профиля |
| `reg export HKLM\...\Policies` | Изменение политик |
| `bcdedit /export` | Правки загрузчика |
| `dd`/`sgdisk --backup` MBR+GPT | Любые операции с разделами |
| Полный образ диска (Clonezilla) | Всё, что идёт после |

## P10. Паттерн «Идемпотентность + dry-run» для всех скриптов

Каждый скрипт: `-WhatIf/--dry-run`, лог в файл, ненулевой код возврата при
ошибке, разрушающие действия только по явному флагу. Повторный запуск безопасен.
Закреплено в `CONVENTIONS.md`, раздел 5; используется в enforcement-задаче (P5).

---

## P11. Паттерн «Раздел-хранилище состояний» (State Partition)

**Суть.** Раздел `Tools` (NTFS, 128 ГБ) — не только утилиты, но и **состояние**:
журналы работ, бэкапы профилей, экспортированные драйверы, enforcement-логи,
эталоны конфигов.

**Причина выбора именно NTFS:** поддерживает ACL (нужны для P4-слой 6) и
большие файлы (VHDX, образы), чего exFAT не даёт.

---

## P12. Анти-паттерны, которые в работу не берём

| Анти-паттерн | Почему не берём |
|--------------|-----------------|
| Полное отключение pagefile | Ломает crash dump и стабильность при 8 ГБ RAM (I3) |
| Отключение flush кэша записи | Риск потери данных без UPS (I4) |
| Блокировка драйверов через подмену файлов | Требует подписанных драйверов / даёт BSOD-риск — исключено требованием |
| Использование IFEO как security-контроля | Обходится флагом `DEBUG_PROCESS` (E3) |
| `auto_install` с `"image"`-маской | Дефект Ventoy — меню выбора не появляется (K3) |
| «Последняя версия» debloat-скрипта без фиксации | Конфликт требований версий (J4) |
| Копирование `Login Data` Chrome как способ переноса паролей | DPAPI-привязка, на новой машине не расшифруется (L4) |
