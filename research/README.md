## Пул дефектов и протокол возврата

Пул живёт в `bestiary.csv`, правило — в `CONVENTIONS.md` раздел 12,
проверка пула — `tests/test_bestiary.py`.

Запись закрывается только возвратом дефекта: проверяемое состояние
воспроизводится в копии репозитория, прогон падает, копия удаляется.
Протокол прогона, применённый 2026-10-15:

```bash
rm -rf /tmp/rd && cp -r <репозиторий> /tmp/rd
find /tmp/rd -name __pycache__ -type d -exec rm -rf {} +   # кэш ломает возврат
cd /tmp/rd
python3 -c '<мутация>'                 # воспроизвести дефект класса
python3 tests/<проверка из closes>     # обязана упасть
cd - && rm -rf /tmp/rd                 # копия удаляется, оригинал не тронут
```

Три условия, без которых возврат недействителен:

1. **`__pycache__` удалён.** Кэш от прежнего эксперимента даёт результат
   прошлого состояния и выглядит как непрошедший возврат.
2. **Копия читает свои файлы.** Пока тесты зашивали абсолютный путь
   (класс `B-10`), копия проверяла оригинал: мутация копии не меняла
   результат, и возврат был физически невыполним.
3. **Мутация одна.** Несколько правок за проход не позволяют сказать,
   какая из них уронила проверку.

Результаты прогона 2026-10-15 — 12 возвратов, каждый роняет свою проверку:

| Класс | Мутация в копии | Проверка | Результат |
|---|---|---|---|
| B-01 | строка в `manifest.csv` без правки `baseline.csv` | `test_rules.py` | 1 FAIL |
| B-02 | `1.1.14` → `1.1.15` во всех `.md` | `test_stage8.py` | 4 FAIL |
| B-03 | битая ссылка сущности в `algorithm.md` | `test_navigation.py` | 1 FAIL |
| B-03 | заголовок «Средства» → «Инструмент» | `test_navigation.py` | 1 FAIL |

`B-04` возвратом не закрывается и помечен как приём: правила «все тесты
нормализуют текст» в репозитории нет — `flat()` определён в трёх тестах из
семнадцати, поэтому требовать его везде значит ломать четырнадцать рабочих
проверок. `B-07` возвращается той же мутацией, что `B-01`. Число находок в `n`
мета-класса `B-09` проверяется пересчётом по разделам «Находки» и
«Расхождения» четырёх AUDIT-документов: взятое из памяти число разошлось с
фактом на 12 (в записи было 48, в документах 36), поэтому теперь оно
сверяется с `tests/baseline.csv`, ключ `audit_findings`.

## Профиль целевой инфраструктуры (фиксируется как константа)

| Параметр | Значение |
|----------|----------|
| Классы объектов | Домашние ПК, малый бизнес, «зоопарк» железа, домашние роутеры и сеть |
| Тип работ | Выездной мастер, **без вскрытия станций** |
| Диапазон задач | Программный ремонт, установка, оптимизация, бэкап, настройка, автоматизация развёртывания, отключение встроенного мусора ОС и вендоров материнских плат и механизмов его самовосстановления |
| Домен/AD | Отсутствует — только локальные GPO (`LGPO.exe`) |
| Сеть у клиента | Недетерминирована: каждый шаг алгоритма обязан декларировать требуемое состояние сети |
