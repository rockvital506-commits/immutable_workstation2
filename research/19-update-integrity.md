## 2. Расхождения и находки

### N1. Сверяются только ISO — 23 бинарника вне проверки

`scripts/check-flash.sh`, блок `[4/5]`:

```bash
[ "$mtype" = 'iso' ] || continue
```

В `manifest.csv` 47 строк: 7 `iso`, 23 `tool`, 11 `script`, 6 `module`.
Заполненное поле `file` — у 30 строк, из них **23 не-ISO**. План говорит
«всех образов **и бинарников**», скрипт проверяет только образы.

Вне проверки остаются, в частности: `LGPO.exe`, `VeraCrypt_Setup_x64_1.26.29.msi`,
`SDIO_2.0.4.887.zip`, `Drivers.torrent`, `Autoruns.zip`, `nmap-7.991.zip`,
`rustdesk-1.5.0-x86_64.exe`, `Win11Debloat.ps1`, `Sophia.ps1`, `winutil.ps1`.

### N2. Даже без фильтра путь строится неверно

```bash
target="$VENTOY_MOUNT/$mcat/$mfile"
```

Утилиты лежат на разделе **TOOLS**, а не VENTOY. Переменная `TOOLS_MOUNT`
используется в скрипте только для сравнения набора групп, в сверке сумм не
участвует. То есть простого удаления фильтра `iso` недостаточно: для типов
`tool`, `script`, `module` нужна другая база пути.

### N3. Проверка пуста: 29 строк из 47 без суммы

Статусы: 30 `planned`, 17 `present`. Поля `sha256` нет у 29 строк — у всех
семи ISO и у 22 утилит. Скрипт на это отвечает предупреждением «нет SHA256 —
сверить нечем» и завершается с кодом 0.

**Следствие, которое важнее самого пробела.** Все ISO — `planned`, то есть
образов на флешке ещё нет. Значит сверка не может пройти не потому, что суммы
не заполнены, а потому что **сверять нечего**. Система проверки целостности
не выполнена ни разу ни на одном реальном файле. Это надо зафиксировать как
факт, а не как «проверка работает».

### N4. Парность соблюдена, но hollow-проверка продублирована

`check-flash.ps1` содержит тот же фильтр и тот же путь
(`Get-FileHash`, `-Verify`). Обе версии одинаково не проверяют бинарники.

### N5. Регламента обновления нет

Единственное место — `reinstall.md`, шаг 2: абзац про Update против Install.
Ответов на вопросы плана нет:

- что можно обновлять на месте;
- что требует переустановки Ventoy;
- в каком порядке;
- что проверить после.

### N6. Факты про обновление Ventoy, которые надо внести в регламент

- **Update сохраняет файлы** на разделе данных, Install — стирает. Утверждение
  в `reinstall.md` верно, подтверждается несколькими источниками.
- **Но это спроектированное поведение, а не замена бэкапу.** Перед крупным
  обновлением критичное надо копировать. Эту оговорку я не написал.
- **Смена MBR ↔ GPT требует переустановки Ventoy, не обновления.** Наша
  флешка — GPT; случай, когда это понадобится, редкий, но регламент должен
  его называть.
- **С 1.1.14 нужна запись ключа UEFI CA 2023** при первой загрузке — это
  относится и к обновлению, не только к установке.
- **До 1.1.16 VentoyPlugson сбрасывал `VTOY_WIN_UEFI_RES_LOCK`**, а у нас в
  конфиге значение 3. Вывод: на версиях до 1.1.16 конфиг через Plugson не
  править.
- Обновление самого Ventoy и обновление содержимого (образы, утилиты, скрипты)
  — **две разные процедуры**, сейчас они смешаны в одном абзаце.

### N7. Бэкапа разделов нет вообще

Поиск по «бэкап раздел», «резервн… раздел», «копия раздела» — ноль. В корневом
`README.md` есть фраза «всё ценное с него бэкапится» — как констатация, без
процедуры. Существующие средства в `tools/backup/disk_image/` относятся к
дискам **станций**, не к разделам флешки.

### N8. Противоречие в назначении `ventoy-partition/backup/`

| Источник | Что говорит |
|----------|-------------|
| Корневой `README.md`, строка 40 | «дампы MBR/GPT как есть» |
| Корневой `README.md`, строка 76 | «Дампы первых секторов диска» |
| `PLAN.md`, строка 14 | «дамп первых секторов диска … до любых правок» |
| `tools/README.md`, строка 69 | «**Бэкапы клиентов и образы машин** — только в `ventoy-partition/backup/`» |

Три источника говорят про дампы секторов, один — про образы клиентских машин.
Это разные вещи, и второе утверждение опасно: оно предлагает хранить резервные
копии клиентских данных **на том же носителе, с которым мастер работает**.

Фактическое состояние каталога: **пуст**, только `.keep`. То есть дамп первых
секторов, который `PLAN.md` предписывает снять до любых правок, не снят.

### N9. Средство для бэкапа разделов уже на флешке

`ISO/backup/clonezilla-live-3.3.3-37-amd64.iso`. По правилу комплектования
TOOLS (сначала Strelec, затем портативный бесплатный аналог) брать стороннее
средство не нужно: Clonezilla умеет образ раздела, бесплатна, GPL, уже есть в
манифесте. Требование — 196 МБ ОЗУ, грузится в BIOS и UEFI.

Ограничение, которое надо учесть: **Clonezilla не снимает образ
смонтированного раздела**, и целевой раздел при восстановлении должен быть не
меньше исходного.
